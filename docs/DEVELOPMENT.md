# تطوير VANTARA والتحقق من التغييرات

هذه تعليمات عمل لمطور يفتح المستودع للمرة الأولى. **لا تنشر ملفات APK أو Windows ولا تعدّل Cloudflare لمجرد نجاح الاختبارات محليًا**. الدمج والنشر يحتاجان اعتماد مالك المشروع.

## المتطلبات

- **Node.js 22+** و**pnpm 10.33.0** (مذكوران في `package.json`).
- أدوات Android SDK وJDK/Gradle لبناء التطبيق الأصلي.
- بيئة Windows مناسبة لبناء/اختبار مثبت Electron ومشغّل mpv ومحرك rqbit؛ اختبارات Linux لا تثبت وحدها جودة الفيديو على Windows.
- Docker وقاعدة البيانات فقط عند العمل على خدمات `apps/api` والمكدس المستضاف ذاتيًا.

## البداية السريعة

```bash
corepack enable
pnpm install

# الواجهة فقط
pnpm test:web

# حراسة العقود والملفات العامة
pnpm test:safety

# نطاق الحزم التي تعلن فحص أنواع أو lint
pnpm typecheck
pnpm lint

# الاختبارات المجمعة للخلفية والواجهة
pnpm test
```

**ملاحظة:** `pnpm dev` في الجذر يبدأ `@vantara/api`، وليس خادم واجهة المتصفح. لا تعتبر فتح `index.html` مباشرة بديلًا عن بيئة HTTP المناسبة للـPWA والمزامنة.

## تشغيل واختبار كل منصة

| المطلوب | المسار أو الأمر | التحقق الضروري |
| --- | --- | --- |
| تطبيق الويب | `apps/web/` و`apps/web/pwa/` | متصفح حقيقي + مصادر قابلة للوصول + تجربة تحديث PWA |
| اختبارات الويب | `pnpm test:web` | نجاح اختبارات الوحدة، ثم تجربة المسار المتأثر |
| Android debug | `npx cap sync android` ثم `cd android && ./gradlew :app:assembleDebug` | build مناسب للمعمارية + تجربة جهاز أو محاكي |
| Windows Desktop | `apps/desktop/`، `tools/build-windows.mjs` | اختبارات Desktop + تطبيق فعلي مع ملفات mpv/rqbit |
| خدمات الحسابات | `services/sync-worker/` | اختبارات العقود والهوية + صلاحيات D1 والتحقق من النشر |
| خادم المحتوى الاختياري | `apps/api/` و`infra/` | Migrations + اختبارات قواعد البيانات + شروط التشغيل |
| ترجمة الصفحات | `services/translation-worker/` | اختبار خطوط/نماذج/صور حقيقية؛ لا تعميم نتائج Fixture واحد |

للتفاصيل المثبتة والخطوات الخاصة بكل بيئة راجع الملفات المتخصصة بدل اختراع أمر بناء واحد لجميع المنصات.

## خريطة تعديل الميزات

| تريد تعديل | غالبًا تبدأ من |
| --- | --- |
| صفحة عمل أو قارئ أو المجلس | `apps/web/v35/` |
| بيانات الكتالوج وهوية الأعمال | `apps/web/lib/` |
| تثبيت الإضافات ومسارات المصادر | `apps/web/addons/` |
| قدرات المنصات ومفاتيح الظهور | `apps/web/lib/release.js` و`capabilities.js` |
| تشغيل تورنت APK | `android/app/src/main/kotlin/com/vantara/addons/torrent/` |
| مشغّل Android | `android/app/src/main/kotlin/com/vantara/anime/player/` |
| تشغيل تورنت Windows | `apps/desktop/src/services.mjs` و`torrent-window.mjs` |
| غلاف/مشغّل Windows | `apps/desktop/main.cjs` و`video-host.cjs` |
| مزامنة/بيانات المستخدم | `services/sync-worker/` و`packages/domain/` |
| تطوير PWA | `apps/web/pwa/` و`services/web-fetcher/` |

## قواعد العمل المهمة

1. **غيّر أقل قدر ضروري**: لا تستبدل محركًا يعمل فقط لتوحيد اللغة أو تقليل الملفات.
2. **لا تتجاوز حدود المنصة**: أنظمة Android الأصلية ليست قابلة للنسخ حرفيًا إلى PWA أو Windows.
3. **احفظ الهوية والتقدّم**: لا تدمج عملين اعتمادًا على تشابه العنوان فقط؛ احترم الهوية والمصدر والموسم والفصل.
4. **عقود البيانات لها مالك واحد**: راجع `packages/domain/src/ownership.ts` و`docs/VANTARA_DATA_OWNERSHIP.md`.
5. **افصل أمان الإضافات عن أمان الحساب**: لا تسرّب Token أو Cookies إلى إضافة خارجية، ولا تتجاوز تقييم URL/redirect.
6. **الاختبار التجريبي ليس اختبار إنتاج**: نجاح seeder محلي أو محاكي لا يضمن تورنت عامًا أو جهاز Windows حقيقي.
7. **لا تضع بيانات شخصية أو أسرارًا في commits أو PRs أو سجلات التشخيص**.
8. **وثّق الأدلة والحدود**: ماذا اختُبر، على أي commit ومنصة وملف، وما الذي لم يُختبر.

## طريق المساهمة أو الإصلاح

1. أنشئ فرعًا محدودًا ووصفًا واضحًا للمشكلة وإعادة إنتاجها.
2. حدد الملفات المتأثرة والعقود التي تعتمد عليها.
3. أضف اختبار انحدار حيث يمكن قبل الإصلاح أو معه.
4. شغّل الاختبارات ذات الصلة و`pnpm test:safety`؛ لا تعتبر فشل فحص ما «غير مهم» بلا تفسير.
5. عدّل التوثيق المناسب إذا تغيّر سلوك المنتج أو حدود المنصة.
6. افتح PR يذكر: السبب، التغيير، نتائج الاختبارات، نتائج تجربة الجهاز، وما لم يُختبر.
7. **لا تدمج ولا تنشر** إلا بعد توجيه صريح من مالك المستودع.

## النشر والإصدارات

- `main` يتصل بسير عمل CI والإصدارات والتوزيع؛ تغيير Markdown في PR لا يعني إصدارًا جديدًا.
- قد تظهر حزمة Android أو الويب قبل انتهاء بناء Windows؛ راجع **ملفات الإصدار نفسه** للتأكد.
- تأكد من أصل الثنائيات وبصمات SHA256 عند توزيع حزم Windows/APK.
- الشرح المعتمد لمسار التحديث: [UNIFIED_UPDATES](UNIFIED_UPDATES.md)، والتاريخ الفعلي: [GitHub Releases](https://github.com/Meshal515/VANTARA/releases).
- `docs/DEPLOY.md` يختص بمكدس المحتوى الذاتي؛ **ليس دليل نشر شاملًا لكل خدمات VANTARA**.
