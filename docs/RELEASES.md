# الإصدارات والقدرات ومفاتيح الميزات

VANTARA منتج واحد بمنصتين: **APK** (أندرويد) و**PWA** (المتصفح: آيفون، آيباد،
كمبيوتر). نشارك الهوية والحساب والبيانات والوظائف العامة والتصميم، ونختلف فقط
حين تفرض قدرة المنصة ذلك.

## الملفات

| الملف | ماذا فيه |
|---|---|
| `apps/web/lib/release.js` | بيان الإصدار: `version`، `schemaVersion`، `minimumSupported`، `features`، `flags`، `releases` |
| `apps/web/lib/capabilities.js` | `supports(name)` و`currentPlatform()` — القرار الوحيد في الواجهة |
| `apps/web/lib/migrations.js` | ترحيل البيانات المحلية المرقّم، يعمل قبل أي قراءة |
| `apps/web/pwa/update.js` | تحديث الـPWA الآمن (تنزيل بالخلفية ← «تحديث جديد متاح» ← تطبيق بضغطة) |

## القاعدة: لا اسم منصة في الشاشات

```js
// لا
if (isPwa) …   if (isAndroid) …   if (Capacitor) …
// نعم
if (supports('rafiq')) …
```

`supports()` تجمع شيئين:

1. **القدرة** (`features`): ما تقدّمه المنصة أصلًا.
   `manga: ['apk','pwa']` مشتركة · `rafiq: ['apk']` حصرية للـAPK · `webSources: ['pwa']` حصرية للويب.
2. **المفتاح** (`flags`): لميزة جديدة تحت التجربة.
   `{ enabled, platforms?, accounts? }` — `enabled: false` يطفئها في كل مكان،
   `platforms` يحصرها في منصة، `accounts` (أسماء المستخدمين) لحسابات بعينها.

ميزة غير مدعومة **تُخفى** (لا زرّ ميت، ولا «غير مدعوم» في كل مكان).

إضافة ميزة جديدة = سطر في `features` (ومفتاح في `flags` إن كانت تجريبية) +
`supports('اسمها')` حيث تُعرض. لا شيء غيره.

## الإصدارات

- **إصدار المنتج** (`RELEASE.version`): ما يصفه سجل التحديثات. لا يتغيّر مع كل
  دمج، بل حين نجمع تغييرات تستحق سطرًا للمستخدم.
- **بناء الـAPK**: رقم من CI (`appVersion()`)، ونظام تحديثه كما هو
  (`lib/updater.js`، بيان GitHub، حزم الواجهة بالبصمة الأصلية).
- **بناء الويب**: بصمة القشرة (`SHELL_DIGEST` في `sw.js`).
- **`minimumSupported`**: أقدم APK/ويب ما زال يتكلم مع البيانات بلا كسر.

## سجل التحديثات

`RELEASE.releases`: لكل إصدار بنود `{ kind: new|fix|improve, platforms: [shared|apk|pwa], text }`.
المستخدم يرى المشترك + ما يخص منصته (`releaseNotesFor`)، في الإعدادات ← «ما
الجديد»، ومرة بعد تحديث يطبّقه.

## تحديث الـPWA

```
نسخة جديدة على Pages
  → الـservice worker الجديد ينزّل القشرة كاملة بالخلفية (ذرّي: فشل ملف = النسخة الحالية تبقى)
  → «تحديث جديد متاح» + زر «تحديث» (لا شيء يُطبَّق فجأة وسط قراءة أو مشاهدة)
  → ضغطة: skip-waiting → إعادة تحميل واحدة → ترحيل البيانات → «ما الجديد» مرة
  → بلا ضغطة: يتفعّل وحده في الإقلاع التالي بعد إغلاق التطبيق
```

داخل الـAPK يبقى السلوك كما كان (العامل يتفعّل فورًا ولا يخزّن القشرة).

## التوافق بين المنصتين

أي تغيير في المعرّفات أو حمولات المزامنة أو المكتبة أو التقدم أو النشاط:

- **متوافق للخلف**: حقل جديد اختياري، لا إعادة تسمية ولا حذف لحقل يقرؤه عميل أقدم.
- معرّفات المصادر في الويب **نفس** معرّفات الـAPK، وصيغ الأعمال نفسها
  (`docs/PWA.md`)، فالعمل المحفوظ من منصة يفتح في الأخرى.
- عقد غير متوافق ⇒ مسار أو نوع عملية جديد بإصدار (`…/v2`)، والقديم يبقى حتى
  يتجاوز `minimumSupported` كل الأجهزة.
- ترحيل محلي ⇒ رفع `schemaVersion` + خطوة في `MIGRATIONS`، لا تمسح بيانات حساب.

الحراس في `tools/repository-safety.test.mjs` (عقد المزامنة، عزل الـPWA عن
الـAPK، القشرة) تفشل CI إن كُسر شيء من هذا.
