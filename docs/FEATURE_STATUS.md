# حالة ميزات VANTARA وحدود التحقق

> **مراجعة وثائقية:** 25 أكتوبر 2026 من كود `main` والوثائق المتاحة. هذه **ليست لوحة مراقبة آلية**، ولا تزعم أن كل سيناريو قد جُرّب على أجهزة المستخدمين. راجع [آخر الإصدارات](https://github.com/Meshal515/VANTARA/releases) قبل ذكر رقم نسخة منشورة.

## معنى الحالات

- **موجود بالكود:** رُصدت مكوّنات وتنفيذ أو اختبارات في المستودع؛ لا يعني إثبات الاستخدام النهائي.
- **صالح للتحقق على جهاز:** مسار موجود ويتطلب اختبارات فعلية للمصادر والشبكة والمشغّل المستهدف.
- **تطوير / تجريبي:** له أجزاء أو مواصفات، لكن لا يجوز وصفه كقدرة مكتملة بلا استثناء.
- **خطة:** وصف تصميم أو هدف، لا ميزة منشورة.

## الحالة حسب التجربة

| التجربة | ما أمكن رصده في الكود | حدود الادعاء |

| المشاهدة/القراءة معًا | `v35/together.js` ووحدات `lib/together/` وعقود الغرف | التحقق الشامل بين جهازين وعلى مصادر مختلفة مستقل عن وجود الكود |

| التورنت Windows | rqbit + mpv وجسر بث وكاش وتشخيص | لا توجد مساواة مثبتة في السرعة مع Android؛ محرك libtorrent لويندوز ليس مطبقًا حاليًا |
| PWA | واجهة المتصفح ومصادر ويب وجالب Cloudflare وكاش PWA | لا يتعامل مع تورنت TCP/UDP العادي داخل المتصفح مباشرة |
| الترجمة المرئية | خط ترجمة وملفات نماذج وتجارب واختبارات خاصة | لا تعمم نتائج النموذج على كل مانجا أو تعتبره خدمة جاهزة على كل المنصات |
| التحديثات | APK وPWA وحزم Windows ضمن بنية الإصدارات | تحقق من وجود ملف المنصة فعليًا في كل Release ومن نجاح اختبارات التثبيت |

**مصدر قدرات الواجهة البرمجية:** [`release.js`](../apps/web/lib/release.js). لا تعتبر تعليقات النسخ القديمة أو أقسام `flags` إعلانًا تسويقيًا أو بديلًا لاختبار جهاز.

## معايير إثبات ميزة

**مثال مشغّل فيديو:** تحديد العمل الصحيح ← الحلقة/الفيلم الصحيح ← مصدر وسيرفر صالحان ← الحصول على بيانات حقيقية ← أول إطار معروض ← قفز صحيح ← استمرار تشغيل. وجود رابط أو READY مبكر ليس إثباتًا لكل هذا.

**مثال مصدر مانجا:** بحث ← تفاصيل صحيحة ← فصول قديمة وحديثة ← صور قابلة للفك والقراءة ← انتقال فصل وحفظ تقدّم.

**مثال Together:** دعوتان/جهازان فعليان ← قبول وانضمام ← تجهيز الوسائط بشكل مستقل ← تزامن/وقف/قَفز ← انقطاع ورجوع دون فقد الجلسة ← عزل المجموعة واحترام الصلاحيات.

**مثال Release:** نجاح CI على commit محدد ← بناء الملف الأصلي ← فحص البصمة والتثبيت ← نشره في GitHub Release. الدمج وحده لا يثبت النشر.

## رؤية مستقبلية منفصلة عن الوضع الحالي

- مساحة خاصة لكل مستخدم مع أصدقائه: **تصميم مطلوب وليس نظام عزل مجموعات متعدد المستخدمين مثبتًا**.
- حتى **10 أصدقاء**: سقف مقترح لنسخة مستقبلية؛ لا تدّعي فرضه في الخادم حاليًا.
- استضافة خاصة على Cloudflare أو خادم آخر: فكرة قيد التقييم وليست قدرة إعداد ذاتي جاهزة.
- **خطة الفصل النهائية تشمل المصادر المدمجة للمانجا والأنمي والسينما جميعًا**، وليس الفيديو وحده. مصادر المانجا الـ16 المستقرة **تبقى مدمجة ومفعّلة الآن** وتُفصل **أخيرًا** إلى حزمة إضافات خاصة، بعد التكافؤ الوظيفي واستعادة البيانات ومراجعة الحقوق. لا يعني هذا أنها فُصلت أو أن أي مصدر حُذف بالفعل. راجع [خطة الترحيل والحقوق](SOURCES_TRANSITION.md).

## أهداف وليست نتائج

- بدء تشغيل شبه فوري وتقليل زمن أول إطار: أهداف أداء في [ONE_SECOND](VANTARA_ONE_SECOND.md)، لا وعود مطلقة في شبكات التورنت.
- توسيع المصادر والتغطية والجودات: يتوقف على توفر المصدر واستقلال المضيف وصحة الهوية.
- توسيع دعم الأجهزة القديمة: يحتاج توافق ABI ومكتبات أصلية واختبارات تثبيت وتشغيل.
- الإتاحة العامة/المصدر المفتوح: **توجه مستقبلي**، لا حق تسجيل عام أو رخصة استخدام كود حالية.

## ما ينبغي تحديثه بعد كل اختبار فعلي؟

أضف في تقرير المكوّن: تاريخ التجربة، commit/رقم الحزمة، المنصة والجهاز، نوع المصدر/الملف، النتيجة، الفشل، وسجل التشخيص المنقّح. ثم حدّث هذا الملخص فقط بما تثبته النتيجة. لا تدرج عناوين أصدقاء أو بيانات دخول أو روابط شخصية.
