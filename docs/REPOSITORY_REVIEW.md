# مراجعة أولية لنظافة مستودع VANTARA العلني

> **نطاق الإثبات:** فحص شجرة `main` ومجموعة ملفات التوثيق/config في 25 أكتوبر 2026. **ليس** تدقيق تراخيص أو حقوق نشر أو مسح أسرار كامل لتاريخ Git، ولا يمكنه إعطاء ضمان بعدم اتخاذ GitHub إجراء.

## حقائق رُصدت

- المستودع **عام** حاليًا، ويضم نحو **1912** مدخلًا في شجرة Git؛ بينها نحو **93 ملف Markdown**. الكثرة ليست مشكلة بحد ذاتها، لكن وثائق من سبتمبر وأكتوبر تصف أحيانًا مراحل لم تعد حالية.
- `README.md` القديم كان يصف المشروع كقارئ مانجا خاص لعدد محدود من المستخدمين؛ هذا لا يمثل تطبيق Android/Windows/PWA الحالي.
- `apps/web/manifest.webmanifest` ووسم الوصف في `apps/web/index.html` كانا يصفانه كقارئ مانجا فقط؛ يحتاجان تحديثًا إذا تغيّرت رسالة المنتج.
- `.gitignore` يستبعد ملفات `.env` ومخرجات الترجمة/البناء والمفاتيح المحلية. `.env.example` يحتوي أمثلة وقيمًا تعليمية (مثل `change-me`)، وليس دليلًا على أن أسرار النشر سليمة.
- شجرة المستودع تتضمن **ملفات APK لإضافات أنمي ومانجا من طرف ثالث** داخل `android/app/src/main/assets/anime-extensions/` و`android/app/src/main/assets/extensions/`. **راجع أصل كل ملف وترخيصه وحق إعادة توزيعه** قبل إطلاق واسع. لا يكفي وصف الملف بأنه «إضافة مفتوحة المصدر» دون دليل.
- لا يوجد ملف `LICENSE` في جذر شجرة `main` التي فُحصت؛ لا يجوز الإعلان أن الكود «مرخّص مفتوح المصدر» إلى أن يُختار ترخيص قانوني وتُراجع تبعياته.
- توجد وسائط اختبار MP4 مؤلَّفة للمشروع بحسب وثائق الاختبار؛ شجرة الملفات وحدها **لا تثبت** خلو جميع المرفقات الأخرى من مواد محمية.

## هل يُغلق GitHub المستودع لمجرد وجود تورنت؟

**لا يمكن استنتاج ذلك.** تورنت والمشغّلات والإضافات تقنيات عامة يمكن استعمالها بشكل مشروع. مخاطر حقوق النشر تتعلق بالمواد المُعاد توزيعها، وحقوق التراخيص، أو المحتوى المخالف الذي تُثبَت عليه مطالبة؛ لا بمجرد كتابة كلمة «تورنت» في الكود أو README.

**لا تُزل أسماء الوظائف لإخفاء النشاط**، ولا تحذف تاريخًا أو أدلة اختبار لمجرد تخفيض حجم المستودع.

## مهام تنظيف عالية الأولوية

1. **تراخيص المكونات الموزعة:** جدول لكل APK وDLL وثنائية ووحدة vendored: المصدر، الإصدار، SHA256، الترخيص، إشعارات حقوق النشر، وحق التوزيع. لا تحذف ملفات يحتاجها التشغيل إلا بخطة بديلة.
2. **فحص أسرار الكود والتاريخ:** فحص Git history والفروع وPRs والمرفقات وإصدارات GitHub وأسماء الملفات وسجلات الاختبار؛ أي سر حقيقي يُلغى/يُدوَّر فورًا. لا تعتمد على جعله Private وحده.
3. **تنقيح البيانات الشخصية:** تعليقات، لقطات، تقارير حيّة، وثائق وإصدارات. إزالة تفاصيل الأصدقاء غير اللازمة من وصف المنتج.
4. **تصنيف وثائق العمل:** واقع/عقود/أدلة/تصميم/أرشيف؛ وضع رابط واضح من `docs/README.md` وإشعار بحالة الوثائق التاريخية بدل حذفها.
5. **قفل وصول الخدمة:** دعوات وموافقات على الخادم، لا مجرد واجهة؛ التحقق من أن الروابط العامة لا تسمح بالوصول إلى حسابات التجربة.
6. **قناة أمان ودليل مساهمة:** وضع قواعد البلاغات وخلوها من أسرار وروابط شخصية وإرشادات إعداد التغيير.
7. **ترحيل مصادر الفيديو إلى الإضافات:** وفق `docs/SOURCES_TRANSITION.md`؛ **مصادر المانجا تبقى**.

## ما لم يتم التحقق منه

- لم يُجرَ مسح آلي شامل لجميع ملفات الكود أو commit history للكشف عن أسرار حقيقية.
- لم تُفحص تراخيص APK الثنائية واحدة واحدة أو إشعارات مكونات Windows/Android.
- لم يُختبر عزل بيانات المجموعات أو التسجيل على إنتاج Cloudflare في هذه المراجعة.
- لم يُنفذ حذف مصادر أنمي/سينما من الكود أو عملية تغيير ظهور المستودع.
- لم تُنفذ اختبارات CI بعد على فرع التوثيق، ولا يعني تحديث README ثبوت جاهزية الإطلاق.
