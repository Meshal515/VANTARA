# إصلاح دخول Android Stable مع الحفاظ على البيانات

الأساس: `main` و`stable-212` عند `f557a61de26f01fb8074c34d7db586006562efd7`.

1. مقارنة حزم Stable الفعلية وDebug، وعنوان المزامنة وCORS والجسر الأصلي. لا تكفي نتيجة البناء لإثبات الدخول.
2. إعادة إنتاج جلسة ناجحة يتبعها `QuotaExceededError` في حفظ التوكن، وفصلها عن فشل الشبكة أو فتح الرئيسية.
3. حفظ سجل جلسة صغير وذري خارج حصة localStorage، مع حفظ إذن PIN الصادر من الخادم فقط. منع استعادة جلسة بعد الخروج، والردود المتأخرة، وخلط مرآة/طابور حسابين.
4. إصلاح اختيار واجهة APK الأحدث عند وجود OTA أقدم؛ لا تغيير لهوية الجهاز أو حماية الخادم أو بيانات المستخدم.
5. اختبار الانحدار، ثم مقارنة baseline/candidate بحزم Release غير debuggable داخل WebView أندرويد فعلي في المحاكي: امتلاء حقيقي، PIN، دخول، مزامنة، ترقية دون مسح، وإعادة تشغيل العملية.
6. رفع الفرع والنتائج للمراجعة، وعرض الأدلة والحدود قبل أي نشر إنتاجي. يبقى حساب الإنتاج وقاعدة بياناته خارج تجارب fixture.
