# خطة التحقيق في أداء ترجمة المانجا

المرجع: طلب المالك في 17 أكتوبر 2026؛ الأساس `3e2885f80b4da1c3d30eaa57340226b4fa2e9014`.
التنفيذ في فرع مستقل. أذن المالك لاحقًا بالدمج والنشر بعد اكتمال التحقق. الاختبارات المصطنعة لا تثبت سرعة الهاتف.

## القيود
- بوابة استدلال ثقيل واحدة؛ سقف الذاكرة والحرارة نافذ.
- لا تخفيض لعتبات OCR أو المسح ولا توسيع للمسار السريع بلا صور وأدلة.
- لا تعديل للفيديو أو التورنت. الويب وAPK يشتركان في سياسة القارئ.

## 1. الجدولة والقياس
- [ ] كتابة اختبارات انتقال التركيز أثناء انتظار استكمال آخر، ازدحام Route، أولوية المسافة الحية، وسقف الذاكرة.
- [ ] تشغيلها على الأساس وإثبات فشل الحالات الجديدة.
- [ ] تعديل `apps/web/lib/translate.js`: السماح بطلب استكمال ظاهر واحد إضافي فقط عند الحاجة، مع استمرار تسلسل Native وحد الذاكرة. تقييد تجاوز التوجيه الاستباقي للتحليل. تمرير ترتيب الصفحة الحي إلى Native.
- [ ] إضافة أثر محدود للأحداث والمالكين والحدود وقرار القدرة، وتمريره عبر `reader-translate.js` إلى تقرير الأداء، دون جمع الأزمنة التشخيصية مرتين.
- [ ] تشغيل اختبارات الترجمة ثم تسجيل النتيجة.

## 2. النص المتروك
- [ ] اختبار أن الجزئية لا تُحسب صفحة جاهزة في القارئ وأن تحديث الإصلاح يغلق الانتظار فعليًا.
- [ ] اختبار OCR لإخفاق سطر منفرد لا يختفي عند حساب متوسط ثقة المنطقة.
- [ ] إضافة إعادة قراءة موضعية محدودة للمنطقة/السطر الفاشل بهوامش بديلة، مع عتبة الثقة الأصلية، وحفظ النتيجة حتى لا تُكرر على كل إصلاح.
- [ ] إبقاء الأقنعة وإحداثيات المسح دون تغيير، وتسجيل سبب فشل القراءة، واختبار رفض النتائج غير الموثوقة.

## 3. CTD وBubbleSeg والمصادر
- [ ] مقارنة المصدر المثبت من Yakuyomi وManga Translator وتوثيق الفرق الفعلي عن VANTARA.
- [ ] فحص الأطلس والشرائط والكاش وهندسة الفقاعات ورفض FastROI.
- [ ] إصلاح أي خطأ هندسي قابل للإثبات؛ البدائل التي تغيّر خرج النموذج تبقى تجريبية حتى مقارنة الصور.
- [ ] تحسين قياس المحرك لتمييز التحميل والتشغيل الأول والتشغيل الدافئ المتكرر؛ لا تغيير لإعداد الإنتاج بناءً على توثيق عام فقط.

## 4. التحقق والتسليم
- [ ] اختبارات الويب والسلامة وبناء/اختبارات أندرويد المتاحة، ومراجعة مستقلة للفرق.
- [ ] تقرير يذكر جميع الملفات والنتائج والقيود والمصادر وتعليمات تجربة الهاتف.
- [ ] رفع الفرع وفتح طلب سحب دون دمج أو نشر.

## حالات المراجعة
التنقل السريع، إعادة فتح صفحة جزئية، سقوط صفحة بها سطر فاشل وسط أسطر سليمة، امتلاء handoff، استمرار صفحات التوجيه، اختلاف إحداثيات الأقنعة، وعدم توافر الهاتف/النماذج.

## سجل التنفيذ
الأساس: 190 اختبار ترجمة/قدرة ناجح محليًا. الهاتف وSDK غير متصلين/متوافرين عند البداية. متوافر 11 ملف صفحة حقيقية في المستودع؛ صورة الصفحة صاحبة التقرير غير مرفقة.

تحديث التنفيذ: انتهت المراجعة المستقلة وأُصلحت ملاحظاتها المهمة باختبارات RED→GREEN. نجح 1330 اختبار ويب و54 فحص سلامة، واكتملت 11 صفحة JVM فعلية ومقارنة خيوط CPU بتشغيل أول وثلاث إعادات. تقرير الأدلة: docs/translation-v3-investigation-20261017/REPORT.ar.md.
قرار: لا تغيير لمزوّد الإنتاج أو عتبات FastROI أو رص الأطلس بلا مقارنة بصرية على الهاتف؛ كلفة القرار بقاء العمل الثقيل، وكلفة عكسه بلا دليل احتمال فقد نص أو رسم.
قرار: ميزانية إصلاح جديدة محدودة للإصدار المحلي 4 مع حفظ إصدار البكسلات القديم إلى نجاح الإصلاح، حتى لا تمنع المحاولات القديمة اختبار التصحيح الجديد.
بقيت القياسات الفيزيائية ودقة OCR والعربية على 20–30 صفحة غير مثبتة.
