# نقل انتقائي لتحسينات الإضافات إلى مرشح Stable

الأساس: stable-213، الالتزام c5741f01aa1d6386e7b50c5ddf3a78e1c73ff841، مطابق main عند بدء العمل. فرع النقل fix/stable-addons-selective-20261028 مستقل؛ لا دمج main أو نشر Stable.

## ما نُقل

- واجهة V7: التبويبات والحالات والتشخيص والشعارات وحفظ موقع الرجوع وتصحيح الخلفية والعنوان.
- ربط واجهة مدير المصادر بالجسور الموجودة، دون تغيير وظائف استخراج المصادر الأصلية.
- كشف Cloudflare الصامت وتحقق يدوي معزول، وحماية دورة حياة Activity/WebView، وأسباب فشل مفهومة داخل المصدر فقط.
- عرض صور المصادر عبر مسار جلساتها الموجود، وإلغاء أعمال الواجهة عند إغلاقها.

## ما استُبعد عمدًا

- إعدادات وقناة وتوقيع Debug، ومحدّث التطبيق وتغييرات AppUpdatePlugin.
- مصادر الأنمي/المانجا وحزمها المدمجة ولقطة تعريفاتها. أُضيف إصلاح CI محصور لمولّد الاختبار كي يستخدم الحزم المتتبعة بعد مطابقة الفهرس وSHA-256؛ لا يغير التعريفات أو الإصدارات.
- الحسابات والمزامنة والمشغل والتورنت وإعدادات مستخدم Stable، وملفات البانر وآخر تحديثات المانجا.
- لم تُنسخ بيانات أو إضافات أو مستودعات أو جلسات من بيئة Debug.

حارس tools/android-stable/port-guard.mjs يقارن ملفات حساسة بايتًا ببايت مع Stable المنشور، ويقارن مسارات استخراج الجسور الأصلية ومساعد configureInApp/configureLink. يرفض تعديل حزمة Team X أو وظائف الاستخراج أو إعداد Manifest داخل VANTARA. هذه حماية من تغيير الكود وليست إثبات توفر الموقع الخارجي.

## الفحوص

- بعد النقل:1823/1823 اختبار ويب في198 ملفًا؛ العدد يستبعد اختبارات تحديث Debug المستبعدة من النقل.
- سلامة المستودع54/54، وحارس النقل4/4، وactionlint وفحص Bash وgit diff --check بلا أخطاء.
- فشل حارس بصمة Service Worker أولًا لأن ملف المحدّث أُعيد إلى Stable؛ أُعيد حساب البصمة من محتوى Stable الفعلي، دون مسح التخزين.
- Workflow مستقل بأذونات contents:read فقط: يبني Release بتوقيع Stable الموجود، ومحدد com.vantara.app، ولا يصدر Release أو يغير قناة أو ينشر Cloudflare.
- اختبار Android مستقل مخطط تنفيذه: تثبيت Stable المنشور ثم install -r للمرشح دون uninstall/clear، حفظ تخزين الويب وIndexedDB وهوية الجهاز وملف مستودعات المانجا الحقيقي البنية.30 دورة تنقل و180 ثانية على الأقل مع تسجيل تحدٍّ في coordinator الأصلي دون طلب CAPTCHA؛ فتح صريح لصفحة التحقق ثم إلغاؤها والعودة، وإعادة تشغيل العملية وفحص Logcat.

نتائج Android لا تُسجّل ناجحة إلا بعد استلام أدلة التشغيل. الاختبار لا يسجل دخول حساب إنتاجي ولا يثبت حل CAPTCHA حي أو قراءة مصادر حية؛ مقارنة Team X/MangaSwat الحية ما زالت شرط قبول منفصلًا.

## أول تشغيل مستقل وما تم تصحيحه في أدوات الاختبار

- تشغيل Release 40642094012 توقف قبل بناء APK لأن خطوة اختبار الويب الجديدة لم تبنِ workspace @vantara/domain أولًا.1822 اختبارًا نجح، وملف واحد لم يستطع استيراد الحزمة. أُضيف بناء اعتماد workspace قبل الفحوص؛ لا تغيير في كود الحسابات أو الخادم.
- تشغيل Spike 40642093837 توقف بسبب APKs خارجية محذوفة HTTP404. نُقل إصلاح CI المثبت سابقًا: بايتات الحزم الموجودة في المستودع تُطابق الفهرس المثبت وSHA-256 قبل توليد نفس التعريفات. اختبارات المولّد10/10. لم تُخفَ الاختبارات الفاشلة ولم تتغير أي حزمة أو بصمة مصدر.

- تشغيل Release 40642393716 بنى APK موقّعًا غير debuggable ونجح في ترقية البيانات فعلًا: localStorage وIndexedDB وهوية الجهاز ومستودع المانجا محفوظة. توقف اختبار التنقل عند مقارنة اسم Activity الكامل؛ Android سجله بالاختصار com.vantara.app/.MainActivity. السجل يُظهر MainActivity RESUMED ولا يبدأ التحقق تلقائيًا. صُحّح اختبار الهوية ليقبل تمثيلي Android لنفس المكوّن فقط، مع اختبار يرفض Activity أخرى وحالة غير مستأنفة؛ لم يُخفّف شرط بقاء فانتارا في المقدمة.
