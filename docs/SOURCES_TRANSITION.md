# استراتيجية فصل مصادر المحتوى ونقلها إلى نظام الإضافات

> **قرار معماري مستهدف — 29 أكتوبر 2026:** سيتم فصل **مصادر الأنمي والسينما والمانجا المدمجة جميعها** عن التطبيق إلى حزم إضافات مستقلة قابلة للتحديث والاستعادة. **هذه خطة مستقبلية وليست إعلانًا بأن الفصل تم.** تبقى المسارات المدمجة الحالية تعمل، ولا يُحذف أي مصدر أو محرك أو بيانات قبل اختبار التكافؤ وإمكان الرجوع للإصدار السابق. **مصادر المانجا الـ16 المستقرة تُنقل في المرحلة الأخيرة فقط.**

> **نطاق المستودعات:** مستودع GitHub واحد باسم `VANTARA` للمحرك والتطبيق. لا يلزم إنشاء مستودع رسمي منفصل للروابط أو متجر إضافات VANTARA. يجب أن يظل استيراد مستودعات CloudStream وStremio وMihon وAniyomi الخارجية هدفًا أساسيًا، ولا نُلزم مطوريها بإعادة كتابة إضافاتهم من أجل VANTARA.

**معنى الإضافة المستقلة:** الحزمة لها هوية وإصدار وملفات وتخزين وصلاحيات وتحديثات مستقلة عن إصدار تطبيق VANTARA. تغيير التطبيق لا يحدّث الحزمة بصمت؛ وإن تغيرت واجهة المحرك، يجب الحفاظ على التوافق الرجعي أو دعم Runtime قديم متوافق/منع الترقية مع توضيح الحالة. **الفصل وحده لا يضمن عدم وقوع كسر للتوافق.**

المقصود **فصل مصادر المحتوى**، وليس حذف الكتالوجات أو المشغل أو القارئ أو محرك التورنت. يمكن للإضافة أن تُرجع بيانات العمل والحلقات/الفصول والسيرفرات أو الصور، ثم يتولى VANTARA عرضها بالواجهة الموحدة.

## أولوية التنفيذ

1. **جرد وتجميد خط الأساس:** حصر كل المصادر المدمجة، مكان شيفرتها، اعتمادياتها، معرفاتها، صورها، رؤوس الطلبات، الكوكيز والتقدم المرتبط بها. حفظ نتائج اختبار مرجعية دون نسخ أسرار إلى التقارير.
2. **محرك إضافات متوافق مع الأنظمة الخارجية:** تثبيت عقود `search/catalog → details → episodes/chapters → streams/pages/subtitles` مع محولات CloudStream وStremio وMihon وAniyomi وفق الإمكانات الحقيقية لكل منصة. **المستودع المفهرس لا يعني أن إضافاته تعمل.**
3. **نقل الأنمي والسينما:** تحويل الموصلات المدمجة إلى إضافات قابلة للتثبيت والتشغيل والنسخ الاحتياطي؛ اختبار بيانات عربية حقيقية متاحة بصورة مشروعة أو تجهيزات اختبار مرخصة، بما فيها الحلقة الصحيحة وأول إطار والبحث والترجمة والتبديل الآمن.
4. **الحفاظ على الهوية والبيانات:** استخدام `stable source ID` و`work ID` و`episode/chapter ID`، وجداول تحويل مدققة للمعرفات القديمة. ممنوع نقل التقدم اعتمادًا على تطابق الأسماء وحده. لا حذف أو تغيير تلقائي في `library` أو `progress` أو `IndexedDB` أو بيانات المحرك الأصلية.
5. **التوافق الرجعي والإصلاح والاستعادة:** اختبار الترقية في مكانها والتراجع، تشغيل حزمة قديمة مع إصدار تطبيق أحدث، إعادة التثبيت دون فقد التقدم، وحفظ نسخة احتياطية من الحزم المسموح بالاحتفاظ بها وتوزيعها.
6. **فصل المانجا الـ16 أخيرًا:** إنشاء نسخ **معزولة موازية** من المصادر نفسها، واختبار البحث والتفاصيل والفصول والصور والترتيب والكاش والأداء والحفظ على Android/Windows/PWA بحسب المحرك الفعلي. لا إلغاء لتعريفاتها المدمجة حتى تتساوى النتائج ويُختبر الرجوع. أي مصدر غير قابل للفصل الآمن يبقى مؤقتًا كما هو.
7. **التنظيف بعد النجاح فقط:** إزالة تعريفات المصدر المدمجة التي ثبت استبدالها، في تغييرات صغيرة قابلة للتراجع؛ إبقاء القارئ والمشغل والموصلات العامة. التحديثات المستقبلية للتطبيق لا تُنشئ إعادة تثبيت قسرية لإضافة خاصة ولا تستبدلها بحزمة عامة.

## خصوصية المصادر الـ16 وإعادة الاستعادة

- **القرار المستهدف:** الحزمة/الحزم المنفصلة الخاصة بمصادر المانجا السابقة مخصصة للمستخدمين المصرح لهم فقط (المالك ودحمي ومنصور، بعد ضبط هوياتهم وصلاحياتهم فعليًا). **لا تُدرج في فهرس عام، ولا تُرفع شيفرتها إلى مستودع VANTARA العام، ولا تُربط بحزمة APK/PWA عامة دون مراجعة الحقوق.**
- تخزين الحزم في **توزيع خاص بضوابط وصول** لا يعني إنشاء مستودع GitHub ثانٍ؛ يمكن استخدام خدمة/مساحة تنزيل خاصة. إذا اشترط التصميم مستودعًا واحدًا فقط، يبقى كود المحرك في `VANTARA`، وتبقى الحزم الخاصة خارج تاريخ Git العام والتوزيع العام.
- كل حزمة تُعرَّف بـ`package ID` وإصدار ثابت وتوقيع/بصمة وفهرس استعادة خاص. يجب التحقق من سلامة الحزمة قبل تحميلها، والاحتفاظ بإمكانية التراجع إلى نسخة صالحة سبق تثبيتها.
- **لا تُضمَّن مفاتيح التنزيل الخاصة أو رموز الدخول داخل الشيفرة أو APK أو PWA.** وصول الأجهزة/الحسابات الثلاثة يخضع لمصادقة فعلية وصلاحيات قابلة للإلغاء، وليس إخفاء الرابط فقط.
- إعادة تثبيت حزمة لا تساوي استعادة مكتبة المستخدم تلقائيًا: يلزم نسخ احتياطي منفصل وآمن للمكتبة والتقدم، وتجربة استعادة كاملة. **الحذف المتعمد للتطبيق أو البيانات قد يمسح التخزين المحلي؛ لا يمكن الوعد ببقائها دون نسخة احتياطية.**
- لا تُوزّع أي حزمة خاصة قبل توثيق أصل شيفرتها والتصاريح الملائمة لها؛ تخصيص الحزمة لثلاثة مستخدمين لا يعفي تلقائيًا من شروط التراخيص أو حقوق أصحاب المواقع.

## سياسة الحقوق والتراخيص والأمان قبل كل فصل أو نشر

هذه سياسة هندسية وتشغيلية، وليست إقرارًا بأن كل الحقوق تمت مراجعتها أو استشارة قانونية.

### 1. ملكية الكود وحقوق الإضافات

- **شيفرة VANTARA الأصلية:** يحدد أصحاب حقوقها ترخيصًا مكتوبًا. **AGPL-3.0 خيار مطروح وليس ترخيصًا مُعتمدًا تلقائيًا**. يلزم قرار صريح وملف `LICENSE` كامل ومتوافق مع مساهمات الأطراف الثالثة قبل ادعاء أن المشروع منشور تحت AGPL-3.0.
- **محركات ومكتبات الغير:** سجل منشأ كل جزء، صاحب الحقوق، اسم الترخيص ونسخته، ملفات `NOTICE`، وشروط الإسناد وإعادة التوزيع والتعديل وإتاحة المصدر. لا تنسخ كود CloudStream أو Mihon أو Aniyomi أو مكتباتها إلى محرك جديد دون مراجعة التوافق والترخيص. التوافق مع الواجهة البرمجية لا يعني أن الشيفرة أو حزمة الإضافة أصبحت ملكًا لـVANTARA.
- **الإضافات المستوردة:** يملك ناشروها حقوقهم وفق تراخيصهم. فهرسة روابط مستودع خارجي تختلف عن **استضافة/نسخ/تعديل/إعادة نشر** ملفه؛ قبل إعادة نشر أي حزمة يلزم الإذن أو الأساس الترخيصي الملائم.
- **مصادر المانجا الـ16 الحالية:** كونها مدمجة سابقًا لا يثبت أنها مملوكة للمشروع أو قابلة للتوزيع. يجب تدقيق أصل كل ملف/مُحلل/أيقونة وأي أجزاء مأخوذة من مشاريع أخرى على حدة قبل فصلها أو نشرها.

### 2. حقوق المحتوى والخدمات

- إضافة المصدر لا تمنح VANTARA حقوق نشر أو إعادة توزيع الأنمي أو الأفلام أو الصور أو صفحات المانجا أو الترجمة أو أغلفة الأعمال والعلامات التجارية.
- لا تُحوَّل عناوين التحميل أو ملفات الوسائط المحمية إلى مكتبة عامة أو خادم CDN تابع لـVANTARA دون أساس قانوني. يُحترم اشتراط تسجيل الدخول والقيود الإقليمية وDRM وشروط الوصول، ولا يُقدَّم تجاوزها كميزة.
- استخدام شعار أو اسم الموقع للإشارة إلى مصدره لا يعني الشراكة أو التأييد. تُعرض الإضافة الخارجية مع ناشرها ورابطها وحالة التحقق، وتُزال الروابط أو الحزم عند مطالبة حقوقية معتبرة وفق إجراءات واضحة.

### 3. سلامة سلسلة التوريد والخصوصية

- افصل صلاحيات الشبكة وملفات المستخدم والتخزين لكل إضافة؛ عدم تمرير كلمات المرور أو جلسة VANTARA أو بيانات الإضافات الأخرى إليها.
- فحص البصمات/التوقيعات وهوية الناشر قبل تثبيت أو تحديث حزمة قابلة للتنفيذ. احظر التنفيذ التلقائي لكود غير موثوق في PWA؛ تدعم المنصات صيغًا مختلفة بحسب قدراتها.
- لا تصادق تلقائيًا على نطاق جديد عند Auto-Healing إلا بعد دليل موثوق (تحديث من الناشر/تحويل موثق وفحص الهوية)؛ نتائج البحث وحدها ليست تفويضًا باستبدال المصدر.
- سجلات الأعطال وتقارير الاختبار تُنقح من التوكنات والكوكيز والعناوين الخاصة وبيانات الحسابات. الحزم الخاصة لا تُرفع إلى CI عام أو Artifacts قابلة للتنزيل لكل الزوار.
- يتطلب إصدار عام اختبار تثبيت وترقية ورجوع، مع مراجعة تراخيص التبعيات/الحزم والخصوصية وسيناريو توقف موقع خارجي.

### 4. بوابة إطلاق إلزامية

قبل نشر أي محرك أو حزمة أو ملف مصدر: **ملكية/ترخيص موثق → تصريح/حقوق توزيع عند الحاجة → فحص توقيع وتبعيات → اختبار توافق على المنصات → اختبار حفظ البيانات والرجوع → مراجعة الخصوصية والأمن → موافقة المالك.**

## معايير القبول قبل إزالة المصدر المدمج

- اختبار **المسار الكامل**: تثبيت/فتح المصدر → بحث/كتالوج → عمل صحيح → حلقة وفيديو أو فصل وصور → استمرار/قفز/انتقال → حفظ وإعادة فتح.
- مصادر المانجا الـ16 تحقق **تكافؤًا وظيفيًا** مع النسخة المدمجة السابقة دون انخفاض جوهري في الأداء أو فقد صفحات/فصول، ويكون الاختبار على عينات قديمة وحديثة.
- تحديث VANTARA لا يغيّر إصدار الإضافة المثبتة، ولا يلغي صلاحيتها بلا مسار توافق أو إصلاح واضح.
- نسخة احتياطية موثوقة للحزم الخاصة وحالة التثبيت؛ إعادة تثبيتها ممكنة للمصرح لهم مع استعادة مستقلة لبيانات القراءة والمشاهدة.
- كل تغيير قابل للتراجع ومغطى باختبارات؛ لا يمسح المكتبة أو التقدم أو المصادر الأخرى، ولا يعبث بمحرك التورنت الحالي.
- أي إضافة لا يمكن تشغيلها لسبب تقني أو تقييد جغرافي/شبكي يُعرض سببها بدقة، دون ادعاء نجاح وهمي أو تحميل المستخدم/المصدر مسؤولية غير مثبتة.
- لا يُنقل أي كود أو محتوى طرف ثالث دون مراجعة حقوقه؛ **عدم وجود شكاوى لا يساوي امتلاك الإذن.**
