## 0) اقرأ قبل أي سطر كود

### قواعد ملزمة (من `CLAUDE.md` وقرارات المالك)

1. **كل ما يُكتب للمالك بالعربية**: الرسائل والتقارير ورسائل الـcommit وطلبات الدمج. الإنجليزي لأسماء الملفات والأوامر والمعرّفات فقط.
2. **لا دمج في Debug ولا main، ولا نشر APK أو ويندوز، إلا بأمر صريح من المالك.** اعمل على فرعك وادفعه.
3. **لا فقد لأي بيانات مستخدم:** تقدّم، علامة قراءة، غلاف، قرار دمج، مكتبة. أي تغيير في مفتاح أو مخزن يقرأ القديم مع الجديد.
4. **لا تحذف مصادر المانجا ولا تستبدل محركًا مستقرًا بدافع التنظيم.**
5. **كل بند:** اختبار أحمر على الكود الحقيقي ← الإصلاح ← أخضر ← كل البوابات ← **تجربة المالك على الجوال** ← يُعلَّم «محلول». نجاح CI أو Chromium لا يثبت سلوك WebView أندرويد؛ قل ذلك صراحة واطلب تجربة المالك.
6. **الجذر لا العَرَض:** إن وجدت أن بندين لهما جذر واحد فأصلح الجذر مرة واحدة واذكر البندين.
7. **قواعد الحركة والأغلفة والأنماط في `CLAUDE.md` إلزامية** لأي تعديل CSS أو حركة (العمق عبر `DEPTH_SPECS`، الدخول عبر `page-motion.js`، لا إزالة لما يصل متأخرًا بل `visibility`، `.v35 [hidden]` تعني `display:none`).
8. **قانون تصميم الكمبيوتر** (≥1024 بمؤشر دقيق): لا تمرير أفقي، الاسم والتشغيل في الشاشة الأولى، لا قص للغلاف، لا فراغات عملاقة.
9. الرخصة AGPL-3.0-only: لا كود من مشروع آخر إلا برخصة متوافقة ومسجّل في `NOTICE.md`.

### VI1 · السواد أثناء تحميل صفحة العمل · **3/3**

### SE1 · تحديث الإضافة والرجوع لا يطردان الإصدار القديم من الذاكرة · **كود**
- **الموضع:** `android/app/src/main/kotlin/com/vantara/plugins/ExtensionEnginePlugin.kt:494-497`:
  ```kotlin
  private fun forget(pkg: String) { packages.remove(pkg); loaded.keys.removeAll { it.startsWith("$pkg#") } }
  ```
  معرّف المصدر المدمج سابقًا = اسم الحزمة نفسه أو `pkg@en`، بلا `#`، فلا يُطرد، و`obtain()` (`:1001`) يرجع القديم.
- **يتأثر:** `updateBuiltin` (`:1278`)، و`recover` (`:1324`) الذي يقول «رجعنا لآخر إصدار سليم؛ أعد المحاولة» (`:1234`) ثم يعيد بالكائن المعطوب. `removeBuiltin` (`:278`) يستعمل `splitSourceId` الصحيح.
- **الإصلاح:** الطرد بـ`splitSourceId` (المعرّف = الحزمة، أو `pkg@…`، أو `pkg#…`).
- **اختبار القبول (Kotlin):** بعد `updateBuiltin` و`recover` يرجع `obtain` الكائن الجديد، لكل الأشكال الثلاثة.

## 6) اختبارات الحماية التي لا تُخفَّف

من `MANGA_REMEDIATION_PLAN.md` §3. **أي إصلاح يمس الهوية أو المزامنة يمر بها كلها.**

**منع الدمج الخاطئ:** صفر دمج خاطئ على 1911 عملًا (`manga-identity-bench.test.js`)؛ التتمة والجزء الجانبي لا تشترك بطاقة (842 زوجًا)؛ «X» و«X 2» لا يُدمجان؛ معرّف رسمي واحد لعملين يعرضهما مصدر واحد منفصلين ⇒ لا دمج؛ مطابقة غامضة ⇒ لا دليل؛ التكرار لا يرتفع.

**منع فقد البيانات في المزامنة:** علامة بمرجع قديم تظهر بعد تغيّر المفتاح؛ الأحدث يفوز بين المراجع؛ العلامة المعلّقة تغلب المرآة؛ القراءة عبر المراجع لا تُنتج عملية مزامنة؛ الموضع والغلاف من المرجع القديم؛ المرآة لا تُحفظ بلا تغيير والمؤشر لا يسبق الحفظ؛ فشل الحفظ لا يُسقط `refAliases` ولا الأغلفة.

**للحل ب (لاحقًا):** تشغيل جاف على نسخة D1 بعدد صفوف متطابق؛ لا مرجع يتيم؛ الترحيل يُعاد مرتين بالنتيجة نفسها؛ فك الدمج عكسي؛ جهاز بنسخة قديمة يكتب بالمرجع القديم فيظهر في العمل الجديد.

- **WebView أندرويد وويندوز والمواقع الحقيقية:** لا جهاز ولا SDK ولا Windows هنا. بنود Kotlin مؤكدة بالكود فقط؛ اللقطات من Chromium.

## 8) ما يسلّمه الوكيل بعد كل مرحلة

1. فرع مدفوع ورسائل commit بالعربية.
2. لكل بند: الاختبار الأحمر (اسمه ومخرجه قبل الإصلاح) ثم الأخضر.
3. نتائج البوابات كاملة.
4. **خطوات تجربة المالك على الجوال** لكل بند، بلغة بسيطة وما المتوقع أن يراه.
5. تحديث حالة البند في `MANGA_REGISTER.md` («🔧 أُصلح بالكود والاختبار، بانتظار الجوال»)، ولا «محلول» قبل تجربة المالك.
