## الاستعادة وفهم المحرك

الأساس الفعلي هو `7a266dac8492471948931d3a4e1f600836b44b06` من `codex/vantara-video-repo-debug-20261101`، وليس المرجع التاريخي `35da6719` ولا Claude HEAD `a9826118`. المقارنة مع `cff46bef` تكشف 135 ملفًا تغيرت؛ الشجرة المحلية القديمة محفوظة دون دمج أعمى. Debug المنشور سابقًا 0.0.2370 من `938b5061`؛ APK المبني على 7a كان artifact ولم ينشر.

CloudStream يعمل عبر runtime اختياري خاص بـDebug: مستودع وحزمة مثبتة بالبصمة، تسجيل DEX في عامل منفصل، قدرات وشبكة مقيدة بالمضيف، ثم محول إلى عقد الأنمي والمشغل الأصلي Media3. Aniyomi يستخدم سطح API المتوافق ومحمّل APK الموجود، مع هويات مصادر المصانع ونسخ APK معنونة بالمحتوى؛ لم نضف محركًا بديلًا. Aniyomi داخل عملية التطبيق، لذلك ليس sandbox أمنيًا كاملًا. القيود السابقة موثقة في تقارير الاستعادة؛ الاستيراد والتسجيل وحدهما ليسا توافق تشغيل.

## الأسباب والإصلاحات في هذه الدفعة

- فساد سجل Aniyomi دون backup كان يرمي خلال تحميل الجسر. أصبح الفشل محتوى مع حفظ البايتات ورفض التعديل، وإبقاء الجسر والمصادر المستقلة قابلين للتهيئة؛ لا empty store قابل للكتابة.
- تثبيت/تحديث متأخر كان يستطيع إحياء إضافة حذفها المستخدم أو تجاوز تعديل أحدث. أضيفت tokens بإصدارات الحزمة والمستودع، وفحص CAS وحفظ ثم نشر متسلسلان، والشبكة خارج القفل.
- تحميل adapter متأخر كان يستطيع النشر بعد الإزالة أو إعادة تثبيت البصمة نفسها. أصبح التحقق والنشر ذرّيين مع generation مستقل لمنع ABA.
- الجودات كانت تجمع دقات فعلية مثل 1440 و2160 تحت 1080. أصبحت قائمة الدقات تحتفظ بالارتفاعات الفعلية واختيارها؛ يلزم اختبارها على المشغل الفعلي قبل اعتمادها.
- CloudStream update canary كان يقبل رابط HTTP صالح الشكل ولو أعاد HTML أو403. أصبح يطلب prefixes محدودة عبر نفس وسيط الشبكة والترويسات والكوكيز، ويفحص تواقيع MP4/WebM/TS ومسار HLS حتى segment. المشفر وDASH غير المثبتين لا يمران بهذا الفحص؛ لا تجاوز حماية ولا ادعاء decoding.
- الاستجابات الفارغة كانت تصفر recovery gate. أصبحت العمليات المنتجة وحدها تعيد الصحة، والفراغ المتكرر يدخل مقارنة الإصدار السابق للعملية والمدخل نفسيهما قبل CAS rollback. البحث والصفحات اللاحقة والكتالوج غير المدعوم محايدة.
- فحص الفيديو محدود في العدد والبايتات والعمق والمهلة؛ إلغاء coroutine يغلق اتصال HTTP الفعلي. حد بقية استجابات المحرك لم يلغ.
- سباق fake timers في اختبار hero أصلح في الاختبار فقط دون تغيير سلوك المنتج أو تخفيف assertions.

## متابعة الجولة الثانية

- فحص HTTP حقيقي محلي كشف أن إلغاء socket كان يتحول إلى CANDIDATE_MEDIA_UNVERIFIED؛ صار يتحقق من cancellation قبل إسناد الفشل للمصدر. الإلغاء300ms اجتاز مع إغلاق الاتصال،لا انتظار مهلةHTTP10ثوان.
- RuntimeSourceAdapter كان يسقط روابطhttp لدى parser الآمن المشترك. صار CloudStream وحده يحاول HTTPS لنفس المضيف والمنفذ الافتراضي قبل admission؛ لا cleartext fallback ولا إضعاف TLS أو حدود عناوين الشبكة. حالة الاختبار الحقيقية RED:0مرشحات ثم GREEN:الرابطHTTPS،وتبقى credentials/private/nonstandard ports مرفوضة.
- مصدر Akwam الفعلي يكتب بعض الوسائطhttp،لكن توفرTLS على المضيف ما زال يحتاج الفحص الحي. لا نعلن إصلاح Akwam قبل النتيجة.
- المختبر صار يستخدم عميل وسائط المشغل الفعلي بدل rawOkHttp،ويختبر decoded frames والجودات عند تفعيل vantaraNativePlayback. التقرير لا يقبل media bytes بدل هذا الدليل.
- البحث المتعثر في Aniyomi يبقى FAIL لكنه لا يمنع جمع دليل الفيديو المستقل. لا يحوّل نجاح الفيديو رحلة بحث فاشلة إلى PASS.
