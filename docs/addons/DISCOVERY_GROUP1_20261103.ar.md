# المجموعة الأولى: هوية العمل واكتشاف مصادره

النطاق: إصلاح المجموعة الأولى من مراجعة المحرك، وإضافة تمييز أفلام الأنمي الذي طلبه المالك أثناء التنفيذ. بقية مجموعات التشغيل والتثبيت والشبكة في التقرير السابق ليست مغلقة بهذا التغيير.

## الأسباب والإصلاحات

| السبب المثبت | التغيير |
| --- | --- |
| مطابقة الكلمات تسمح بتبديل أرقام الموسم والجزء | فصل هوية الموسم والجزء والنوع عن تشابه العنوان، مع التعامل مع الأرقام العربية والترقيم الروماني وصيغ المواسم الإنجليزية والعربية. |
| أول تطابق يمنع تجربة الأسماء البديلة المتبقية | تعاد أول نسخة فورًا، ثم تستمر بقية الأسماء في الخلفية، ويصل ما يُكتشف لاحقًا إلى جلسة الاختيار. الإلغاء يبقى نافذًا. |
| كاش معرّف العمل يتجاوز المصدر المختار صراحة | نطاق الذاكرة يشمل معرّف المصدر ورابط نسخته. لا تحفظ زيارة مصدر محدد نفسها كنتيجة البحث العام. |
| وصول مصدر متأخر يستبدل الكاش بآخر دفعة فقط | تُحفظ نتيجة الاكتشاف المدمجة، بما فيها المصادر التي وصلت سابقًا من العائلة الأخرى. اختبار فعلي أعاد إنتاج اختفاء نسخة Kitsu من الكاش بعد وصول WitAnime. |
| الكاش القديم قد يحتفظ بنتيجة قبل تصحيح المطابقة | نتائج المطابقة الجديدة تستخدم `vantara.anime.found.v2`. لا تُقرأ نتائج v1 غير الموثقة بالمطابقة الجديدة، ولا تُحذف بياناتها. |
| البحث الأصلي يسأل الصفحة الأولى فقط | الصفحات تصل تدريجيًا داخل المهلة الإجمالية القائمة؛ سقف 20 صفحة لكل استعلام ومصدر، مع إيقاف الصفحات المكررة. التوقف مع استمرار `hasNext` يُبلّغ كبحث غير مكتمل. |
| الزاحف يخلط مخزون الجولة السابقة بتكرار الصفحة الحالية | تكرار الصفحات يُحسب داخل الجولة الحالية، فتُجتاز صفحة أولى قديمة للوصول إلى أعمال جديدة لاحقة. نقطة الاستئناف وإعادة المحاولات باقية. |
| كاش حلقات الإضافات القديمة لا يتحقق من تغيّر محوّلها | كل عائلات المصادر تتحقق من هوية المحوّل قبل إعادة الكاش وبعد انتهاء جلب الحلقات؛ إزالة المحوّل أو تغييره تمنع إرجاع روابط الإصدار السابق. |

## الأفلام

النوع مصدره بيانات `MOVIE`، وليس عدد الحلقات. العمل التلفزيوني ذو الحلقة الواحدة يبقى عملًا تلفزيونيًا. الفيلم يعرض المدة وأزرار مشاهدة الفيلم، ولا يعرض شبكة حلقات أو خيار الحلقة التالية؛ ويحتفظ بنوعه في سجل المشاهدة المحلي. النوع يمر إلى المشغّل الأصلي وعناوين سيرفراته ومشاركته.

حل وحدة الفيلم لا يفترض أن المصدر رقّمها بالرقم 1؛ يستخدم مسار وحدة الفيلم الأصلي، وتقبل الإضافة وحدة الفيلم الوحيدة المعرّفة في بياناتها حتى إن رقمتها 0. نقص بيانات نوع المصدر لا يتحول إلى ادعاء يقيني بأنه مسلسل أو فيلم آخر.

## تشخيص Debug

`configure` يعلن حالة Debug من الكود الأصلي. يظهر زر **تشخيص الاكتشاف** في صفحة العمل وورقة السيرفرات في Debug. يعرض سجلًا محليًا يربط العمل بطريقة الدخول والاستعلامات وصفحات المصدر ونتائج المطابقة وقبول النسخة أو رفضها. سبب رفض الإصدار يتضمن هويته المتوقعة والفعلية حين تكون متاحة.

أخطاء المصدر والتحميل والجسر تحتفظ بأصناف الاستثناءات وسلسلة أسبابها ومواقع الاستدعاء. السبب الأعمق يوضع قبل إطارات التغليف حتى لا يخفيه اقتطاع العرض. غياب المحوّل لا يسمى انتهاء مهلة إلا إذا انتهت المهلة فعلًا. فشل الزحف يحتفظ بسبب الخطأ والصفحة بدل عبارة توقف عامة فقط.

السجل محدود بـ24 محاولة و200 حدث لكل محاولة، مع عداد للأحداث المسقطة. لا يُرسل إلى التحليلات؛ تُنقح الروابط وبيانات الاعتماد. زر تحديث السجل يقرأ الأحداث الجديدة؛ وقد تظل الاستعلامات الخلفية تعمل بعد ظهور أول نسخة.

هذا التشخيص يبيّن آخر سبب مسجل ومكانه. لا يثبت تلقائيًا أن سببًا خارجيًا بعينه يفسر كل بلاغ سابق، ولا يغني عن اختبار الهاتف ومشاهدة حلقة كاملة.

## التحقق

اختبارات الانحدار تغطي اختلاف المواسم والأجزاء والأنواع، مصدرًا يحتاج اسمًا بديلًا ثالثًا، الاختيار الصريح ذهابًا وإيابًا، الصفحة الثانية وما بعدها والتكرار والحد والفشل الجزئي، تحديث الكتالوج، تبديل محوّل الحلقات وإزالته، أفلام الأنمي في أنماط العرض والمشغّل وسجل المشاهدة، وسلاسل الأخطاء وتنقيحها وحدود السجل.

الأوامر الأساسية:

```sh
node node_modules/vitest/vitest.mjs run
# داخل apps/desktop:
node --test
# داخل android بعد ضبط JAVA_HOME وANDROID_HOME:
./gradlew -PvantaraRuntimeDebug=true :app:testDebugUnitTest :app:compileReleaseKotlin
# في جذر المشروع:
node --test tools/repository-safety.test.mjs tools/repository-compat/debug-native-inputs.test.mjs
```

تُضاف وحدتا المطابقة والتشخيص إلى قائمة كاش القشرة وتُحدّث بصمتها، حتى تصل الوحدات الجديدة في التشغيل دون اتصال. التغيير لم يُنشر إلى قناة التوزيع ضمن هذه المجموعة.

نتيجة المرور الأخير: 2881 اختبار Vitest في 296 ملفًا بلا فشل (منها 2074 اختبارًا للويب)، و636 اختبار Android بلا فشل مع تفعيل CloudStream، ونجاح `compileReleaseKotlin`. اختبارات سطح المكتب: 145 ناجحًا و4 متجاوزة، وفحوص السلامة وبصمة Debug: 56 ناجحًا بلا فشل. هذه اختبارات آلية وتجميع، وليست شهادة مشاهدة فيلم أو حلقة كاملة على هاتف المستخدم.

رفض مشغّل `pnpm test` المحلي مجلد الاعتماديات المشترك لأنه رابط رمزي. جرى تشغيل الاختبارات مباشرة بالأوامر أعلاه، بعد ربط اعتماديات هذا المجلد وبناء الحزم الداخلية محليًا؛ لم يتطلب ذلك تغيير ملفات الاعتماديات المتتبعة أو نسخ المشروع الأخرى.
