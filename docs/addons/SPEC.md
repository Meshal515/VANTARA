# VANTARA Addon Fabric — المواصفة الرئيسية

> **الحالة:** مسودة للمراجعة من المالك — **لا يبدأ التنفيذ قبل اعتمادها**
>
> **المسار المقترح:** `docs/addons/SPEC.md`
>
> هذه الوثيقة هي **مصدر الحقيقة** لنظام الإضافات الجديد في VANTARA.  
> الهدف ليس تقليد Stremio، ولا زيادة عدد المصادر لمجرد العدد. الهدف هو بناء طبقة إضافات طويلة العمر تركّز على:
>
> **النتائج → الاعتمادية → السرعة → الصيانة → سهولة التشخيص → عدم كسر بقية VANTARA.**

---

# 1. الهدف

نريد نظام إضافات واحدًا يخدم:

- المانجا
- الأنمي
- السينما والمسلسلات
- الترجمات
- بيانات الأعمال
- المضيفات والمحللات

لكن **كل قسم له عقد وسلوك خاص**. لا نحاول إجبار المانجا والأنمي والسينما على نفس شكل البيانات.

النتيجة المطلوبة للمستخدم:

> أستطيع فتح أي قسم، رؤية المصادر المثبتة، الدخول إلى مصدر معين وكأنني دخلت موقعه، لكن داخل واجهة VANTARA، مع بقاء القارئ والمشغل والمكتبة والتقدم والهوية كلها تحت سيطرة VANTARA.

والنتيجة المطلوبة هندسيًا:

> أي مصدر أو بروتوكول خارجي يدخل عبر Adapter إلى عقود VANTARA. لا يوجد مصدر يستطيع فرض واجهته أو التحكم بالمشغل أو بيانات المستخدم.

---

# 2. قواعد غير قابلة للتفاوض

1. **VANTARA Core يجب أن يعمل حتى لو تعطلت جميع الإضافات الخارجية.**
2. **الإضافة لا تملك واجهة VANTARA.**
3. **الإضافة لا تملك المشغل أو القارئ.**
4. **الإضافة لا تملك هوية العمل الأساسية.**
5. **الإضافة لا تملك المكتبة أو التقدم أو الحساب.**
6. **الإضافة لا تستطيع قراءة بيانات إضافة أخرى.**
7. **إضافة واحدة لا تستطيع إسقاط القسم كاملًا.**
8. **النتيجة الجاهزة تظهر فورًا ولا تنتظر بقية الإضافات.**
9. **ظهور Ready لا يفتح المشغل تلقائيًا.**
10. **نجاح البحث لا يعني نجاح التشغيل.**
11. **0 روابط تشغيل = فشل، وليس نجاحًا.**
12. **Cloudflare لا يعني حذف المصدر.**
13. **لا تجاوز CAPTCHA أو أنظمة التحقق آليًا.**
14. **لا تثبيت JavaScript عشوائي داخل سياق التطبيق الرئيسي.**
15. **لا هوية بالعنوان وحده.**
16. **لا دمج خاطئ ولا تكرار أعمال.**
17. **لا إعادة كتابة واسعة للمشروع لبناء النظام.**
18. **المصادر الحالية وAniyomi تبقى وتدخل تدريجيًا عبر Adapters.**

  "name": "MangaLek",

  "protocolVersion": 1,
  "minVantaraVersion": "0.2.0",
  "author": "Example",
  "website": "https://example.com",
  "logo": "https://example.com/logo.png",
  "contentTypes": ["manga"],
  "capabilities": ["home", "search", "details", "chapters", "pages"],
  "languages": ["ar"],

  "permissions": {
    "networkHosts": ["example.com", "cdn.example.com"],

- المثبتة
- المتاحة
- تحتاج تحقق
- متوقفة
- تحتاج تحديث

مع بحث وفلترة.

- الشعار
- الاسم
- القسم
- اللغة
- الحالة
- آخر نجاح
- إصدار الإضافة
- هل تحتاج تحقق

- 🟢 تعمل
- 🟡 متذبذبة
- 🔵 تحتاج تحقق

- 🔴 متوقفة

# 10. Source Mode — أهم تجربة في النظام

إذا ضغط المستخدم على شعار MangaLek:

لا يفتح الموقع نفسه.

يدخل:

```text
VANTARA
→ المانجا
→ MangaLek
```

وتظهر صفحة تشعره أنه داخل MangaLek لكن بواجهة VANTARA.

مثال:

```text
┌──────────────────────────────────────┐
│ [شعار MangaLek] MangaLek             │
│ بحث داخل MangaLek                    │
├──────────────────────────────────────┤
│ الرئيسية | آخر الفصول | الأكثر قراءة │
├──────────────────────────────────────┤
│ [غلاف] [غلاف] [غلاف] [غلاف]         │
│ [غلاف] [غلاف] [غلاف] [غلاف]         │
└──────────────────────────────────────┘
```

كل شيء في الصفحة من بيانات MangaLek.

لكن:

- البطاقات = VANTARA
- صفحة العمل = VANTARA
- المكتبة = VANTARA
- التقدم = VANTARA
- القارئ = VANTARA
- Back stack = VANTARA

# 15. تجربة المانجا

المانجا لها نظامها الخاص.

داخل MangaLek:

```text
[MangaLek]

الرئيسية
آخر الفصول
الأكثر قراءة
التصنيفات
بحث
```

صفحة العمل:

- الغلاف
- الاسم
- وصف المصدر
- الحالة
- المؤلف
- الفصول
- لغة الفصل
- فريق الترجمة إن وجد

الفصل:

يفتح في **قارئ VANTARA**.

لا iframe لموقع المصدر.

إذا فصل تعطل:

زر:

> مصادر أخرى لهذا الفصل

فيحاول VANTARA العثور على نفس الفصل Canonically.

---

# 16. هوية فصل المانجا

لا نكرر خطأ `chapter-1`.

هوية الفصل يجب أن تحتوي:

- canonicalMangaId
- sourceId
- sourceWorkId
- chapter source id
- رقم الفصل
- volume
- context / memo

الفصل 1 من عملين مختلفين لا يمكن أن يشتركا في cache key.

# 24. الترجمات نظام مستقل

الترجمة لا ترتبط بمصدر الفيديو.

بعد اختيار Stream، VANTARA يجمع:

- هوية العمل
- الموسم
- الحلقة
- اسم الملف
- release name
- المدة
- hash إن وجد
- fps إن وجد

ثم يسأل إضافات الترجمة.

مصادر محتملة:

- SubSource
- SubDL
- OpenSubtitles
- أي إضافة عربية أخرى
- الترجمة المرفقة بالفيديو

ثم يوحد النتائج ويزيل التكرار.

# 26. Scheduler

وجود 100 إضافة لا يعني تشغيل 100 طلب.

مثال:

```text
0ms     أقوى 3 مصادر
250ms   مصدران إضافيان
700ms   الاحتياط
1500ms  المصادر النادرة والبطيئة
```

الاختيار يعتمد على:

- صحة المصدر
- سرعة المصدر
- تطابق الهوية
- القسم
- اللغة
- الجهاز
- تاريخ النجاح

# 27. Health System

كل Capability لها Health مستقل.

مثال:

```text
MangaLek

Search       99%
Details      98%
Chapters     96%
Pages        94%
```

مقاييس:

- success rate
- timeout rate
- empty rate
- invalid rate
- p50
- p95
- last success

# 62. نقاط تحتاج قرار المالك قبل التنفيذ

هذه البنود **لا تُحسم من طرف المهندس** قبل مراجعة المالك:

1. هل Source Rail على الجوال أفقي أم Drawer؟
2. هل المصادر المثبتة تظهر دائمًا في Sidebar أم فقط عند دخول القسم؟
3. هل فتح شعار المصدر يدخل Source Mode مباشرة أم صفحة تفاصيل الإضافة أولًا؟
4. هل Source Mode يسمح بزر "عرض جميع المصادر" دائمًا أم في صفحة العمل فقط؟
5. هل ترتيب المصادر يدوي بالكامل أم يدوي + ترتيب صحي داخلي؟
6. هل إضافات Stremio تظهر أسماؤها الأصلية للمستخدم أم توضع تحت مجموعة "Stremio"؟
7. هل المستخدم العادي يرى تفاصيل الصحة والأزمنة أم تظل داخل وضع متقدم؟
8. هل الترجمة الآلية تدخل ضمن نظام الإضافات مستقبلًا أم تبقى خارج هذا المشروع؟
9. هل Store يسمح بإضافات يدوية غير موثقة من أول إصدار؟
10. هل Pin للمصدر يكون لكل Profile أم عالميًا على الجهاز؟
