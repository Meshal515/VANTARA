# VANTARA — الخارطة القادمة

ثلاثة أنظمة كبيرة، كل واحد يبني على ما هو موجود اليوم:

| | النظام | يعتمد على الموجود | يحتاج APK؟ |
|---|---|---|---|
| **F1** | Source Extensions — مصادر تُضاف وتتحدث وحدها | محرّك المصادر، «فحص المصادر»، نظام التحديث (`WebBundleState`) | مرة واحدة (مُحمِّل الإضافات)، ثم لا |
| **F2** | Translation Engine — ترجمة عربية داخل الفصول | القارئ الذكي، `translation-worker/arabic.py`، المزامنة | مرة واحدة (محرّك ONNX)، والنماذج تنزل كبيانات |
| **F3** | Live Reading Rooms — قراءة مباشرة مع الأصدقاء | المجلس، الحضور، الإشعارات، القارئ المتصل | لا — واجهة + Worker |

الترتيب المقترح: **F3 ← F1 ← F2** (انظر آخر الملف).

## F3 — Live Reading Rooms

> مو بث شاشة. كل جهاز يحمّل الفصل من مصادره كالعادة، وVANTARA يزامن حالة الجلسة فقط:
> الفصل، المواضع، الأعضاء، التفاعلات. رسائل بعشرات البايتات.

### التجربة

```
مشعل أنشأ جلسة قراءة
Nano Machine — الفصل 143
[ انضمام ]
```

- الدعوة تصل إشعارًا وفي المجلس، لصديق أو لعدة أصدقاء (حتى 8).
- داخل القارئ: شريط رفيع على الحافة، عليه صور الأعضاء في مواضعهم. خفيف، لا يغطي الصفحة.
- **وضعان**، يبدّل بينهما صاحب الجلسة:
  - **مستقل:** كل واحد بسرعته، وتشوف وين الباقين.
  - **متزامن:** صاحب الجلسة يتحرك والباقون معه. من يمرّر بيده يتحرر تلقائيًا، ويظهر له «ارجع مع مشعل».
- **تفاعل سريع** 😂🔥💀 على مشهد، و**تعليق قصير** (80 حرفًا). يظهران فقاعة عابرة على المشهد نفسه، ولا يوجد سجل محادثة يغطي القراءة.
- **حماية الحرق:** التفاعل مربوط بموضعه. من لم يصل لذلك الموضع لا يراه، بل يرى «٣ تفاعلات تنتظرك هنا» ثم تظهر حين يصل.
- **الفصل التالي:** الجلسة نفسها تكمل ولا تُنشأ غرفة جديدة.
- **الخروج والرجوع:** من يرجع (أو ينقطع نته) يدخل نفس الجلسة، على موضعه أو على موضع صاحبها في الوضع المتزامن.

### البنية

```
الجهاز ──WebSocket──► Durable Object: LiveRoom(roomId)   ◄──WebSocket── جهاز صديق
   │                     │ الحالة في الذاكرة + SQLite الخاص به
   │                     ▼
   └──── /v1/ops ────► D1: live_rooms, live_members (للدعوة والرجوع والسجل)
```

- **Durable Object لكل جلسة**، مع WebSocket Hibernation: لحظي (أقل من 100ms بدل 4 ثوانٍ في `/v1/pulse`)، ولا يكلف شيئًا والجلسة ساكنة. متاح في خطة Cloudflare المجانية (SQLite-backed).
- **الرسائل** (JSON صغير):
  `hello` · `snapshot` · `pos {chapter, page, ratio}` (مرة في الثانية على الأكثر) · `mode` · `follow {page, ratio}` · `react {emoji|text, chapter, page, y}` · `chapter {next}` · `leave`.
- **الفصل عبر المصادر:** كل جهاز قد يقرأ نسخة من مصدر مختلف بعدد صفحات مختلف. الهوية المشتركة هي مفتاح الفصل الموحّد الموجود أصلًا (`ext:<العمل>#n:143`، نفس مفتاح «مقروء»). والموضع يُرسل مرتين: رقم الصفحة في نسخة المرسل، ونسبة التقدم في الفصل. نفس النسخة ← الصفحة، ونسخة مختلفة ← النسبة. وحماية الحرق تعمل بالنسبة، فتعمل عبر المصادر.
- **الرجوع:** الجلسة تعيش 6 ساعات بعد آخر نشاط. `snapshot` يعطي الداخل كل شيء، وموضعه الأخير محفوظ.
- **بلا اتصال:** إن سقط WebSocket يعود لـ`/v1/pulse`، والقراءة نفسها لا تتوقف أبدًا (الفصل محلي).

### المراحل

| | المرحلة | معيار الإنجاز |
|---|---|---|
| R1 | جلسة لشخصين، وضع مستقل، شريط المواضع | جهازان في الأداة (rig)، الموضع يصل في أقل من ثانية |
| R2 | الوضع المتزامن + «ارجع مع مشعل» | المتابع يلحق صاحب الجلسة، والتمرير اليدوي يحرره |
| R3 | تفاعلات وتعليقات + حماية الحرق | لا يُرى تفاعل قبل موضعه، واختبار عبر مصدرين مختلفين |
| R4 | فصل تالٍ بنفس الجلسة، رجوع بعد انقطاع، حتى 8 أعضاء | قطع الشبكة ثم رجوعها، ونفس الجلسة والموضع |

## F1 — Source Extensions

### المشكلة اليوم

الإضافات الست عشرة مدمجة داخل الـAPK (`assets/extensions`)، فهي جزء من بصمة الكود الأصلي. أي إصلاح لمصدر أو مصدر جديد يعني APK. هذا ما نريد إنهاءه.

### التصميم: نفس نمط تحديث الواجهة، للمصادر

```
vantara-sources.json (في إصدار GitHub، يبنيه CI من قائمة في المستودع)
  لكل مصدر: package · versionCode · extensionLib · sha256 · مفتاح توقيع Keiyoushi · رابط
      │
      ▼
تنزيل ← sha256 ← توقيع الإضافة يطابق المفتاح المثبّت ← بوابة extensionLib
      │
      ▼
staged ← مسبار على الجهاز (خطوات «فحص المصادر»: قائمة، بحث، فصول، صفحات، صور)
      │ نجح                           │ فشل
      ▼                               ▼
good (يُستعمل)                    bad، ويبقى الإصدار السابق يعمل
```

- **المدمجة في الـAPK تبقى أرضية** لا تنكسر، والمنزّلة تعلوها فقط إن كانت أحدث وتحققت ونجح مسبارها. نفس فلسفة `WebBundleState`: staged ← trial ← good، ومسار الرجوع عادي.
- **إضافة مصدر جديد:** سطر في قائمة المستودع، ثم دمج ← CI ← الجوالات تجده. بلا APK.
- **سياسة المحتوى:** بوابة `CONTENT_WARNING_SAFE` القائمة تبقى على القائمة، والإضافة من اختيار المالك لا من المستخدم.
- **أمان:** كود الإضافة يُشغَّل على الجهاز. لذلك البصمة من بياننا، وتوقيع Keiyoushi مثبّت لكل حزمة، وأندرويد 14 يشترط أن يكون ملف الـdex المحمّل ديناميكيًا للقراءة فقط (`setReadOnly`).

### المراحل

| | المرحلة | معيار الإنجاز |
|---|---|---|
| E1 | مُحمِّل من `files/extensions` + التحقق (APK واحد) | إضافة منزّلة تُحمَّل بدل المدمجة |
| E2 | بيان المصادر في CI + التنزيل والمسبار والرجوع | إصلاح مصدر يصل بلا APK، وإصدار مكسور يرجع وحده |
| E3 | مصدر جديد من القائمة | يظهر في VANTARA بعد الدمج، بلا APK |

## F2 — Translation Engine

> مو fork بتغيير الاسم. نركب فوق أفضل المشاريع المفتوحة، والقيمة الحقيقية شغلنا:
> العربية، السياق، الذاكرة، الأولويات، الكاش، وتجربة القراءة.

### المسار

```
صورة الصفحة → كشف مناطق النص → OCR → السياق → ترجمة → مراجعة (QC)
           → إزالة النص الأصلي عند الحاجة → رسم العربية RTL → حفظ → عرض في القارئ
```

| المرحلة | من أين | أين تعمل |
|---|---|---|
| كشف المناطق | comic-text-detector (ONNX) | الجوال |
| OCR | manga-ocr للياباني، PaddleOCR mobile للإنجليزي/الكوري/الصيني، اختيار حسب اللغة (فكرة comic-translate) | الجوال |
| السياق والذاكرة والمصطلحات | **VANTARA** | الجوال + المزامنة |
| الترجمة | نموذج لغوي عبر API (Claude)، دفعات من 3–5 صفحات مع السياق | الـWorker (المفتاح لا يدخل الـAPK أبدًا) |
| إزالة النص | تعبئة بلون البالون للبالونات البسيطة، وLaMa للخلفيات المعقدة فقط | الجوال |
| رسم العربية | **VANTARA** | الجوال |
| تشغيل النماذج | ONNX Runtime Android، والمحرك دافئ بين الصفحات (فكرة Yakuyomi) | الجوال |

### ما هو خاص بـVANTARA

- **رسم عربي بلا صور جديدة:** القارئ WebView، ومحرك المتصفح يشكّل العربية ويرتّبها RTL أصلًا (HarfBuzz + ICU). فالترجمة تُرسم طبقة HTML فوق الصورة بإحداثيات المناطق، مع ملء البالون وتصغير الخط حتى يتسع. النتيجة JSON صغير لا صور مترجمة، وتُعاد بخط أفضل متى شئنا. ورسّام `arabic.py` (RAQM + HarfBuzz + FriBidi) يبقى لتصدير صور مركّبة عند «تنزيل للقراءة بلا نت».
- **Context Engine:** الصفحات السابقة، الشخصيات (الجنس، الألقاب، طريقة الكلام)، وأحداث الفصل تدخل مع كل دفعة ترجمة.
- **Glossary لكل عمل:** اسم قدرة أو منظمة تُرجم مرة يبقى هو نفسه في كل الفصول.
- **Translation Memory:** نص تكرر يعيد القرار السابق.
- **Region IDs:** هوية لكل بالون (الصفحة + موضع ثابت)، فالتحديث لا يخلط الفقاعات.
- **QC:** لا بالون متروك، لا عربية خارج البالون، لا اسم تغيّر بين صفحتين، لا ترجمة ناقصة أو مكررة، ترتيب القراءة صحيح.
- **ترجمة وحدة تكفي العيال:** الصفحة تُعرف ببصمة صورتها. إن ترجمها مشعل، فدحمي ومنصور يأخذونها من المزامنة فورًا بلا تكلفة.

### الجدولة — «ادخل بأقل جاهز ممكن»

**الفصول:** الحالي ← التالي ← السابق. طابور أولويات حي لا ثلاث مهام ثابتة. إن اقترب القارئ من صفحة غير جاهزة في الحالي، تُسحب الموارد من التالي فورًا.

**الصفحات:** الأولوية بالمسافة من موضع القارئ، لا بالترتيب 1 ← 100. من في صفحة 30 تُجهَّز له 30، 31، 32 قبل 95.

**المراحل متداخلة:** كشف صفحة 3 أثناء OCR صفحة 2 أثناء ترجمة صفحة 1، بعدد عمّال بقدر الجهاز.

**عتبة الدخول تُحسب ولا تُثبَّت:**
لتكن `N` صفحات الفصل، و`R` سرعة قراءة هذا المستخدم (صفحة/دقيقة، من سجلّه)، و`T` سرعة الترجمة الفعلية الآن.

- `T ≥ R` ← الترجمة أسرع منك، فتدخل عند أول 3 صفحات (أو 10%).
- `T < R` ← ستلحق بها. أقل جاهز يمنع التوقف هو `k = N × (1 − T/R)`، مع هامش أمان 20%.
- الحدود من 10% إلى 60%. فالنسبة تطلع 15% أو 30% أو 50% حسب الجهاز والمصدر والقارئ، لا رقم واحد للكل.

### التخزين

لكل صفحة: بصمة الصورة، المناطق، نص OCR، العربية، معلومات الرسم، إصدار النموذج، والحالة.
ولكل عمل: الشخصيات، المصطلحات، الذاكرة.

الحالات:
`QUEUED → DETECTING → OCR → CONTEXT → TRANSLATING → INPAINTING → TYPESETTING → READY_PARTIAL → READY`

- محلي أولًا (IndexedDB)، ومزامَن للأصدقاء. JSON الصفحة بضعة كيلوبايتات، لا صور.
- لا إعادة ترجمة إلا إن تغيّرت الصورة، أو رُفع إصدار النموذج بقرار.

### المراحل

| | المرحلة | معيار الإنجاز |
|---|---|---|
| T0 | تجربة قياس على فصول حقيقية (كوري ويبتون + ياباني) | زمن الكشف وOCR على الجوال، جودة العربية، تكلفة الفصل |
| T1 | رسّام الطبقة العربية في القارئ | بالونات عربية سليمة فوق صفحات حقيقية (بيانات يدوية) |
| T2 | محرك ONNX على الجوال (APK واحد، والنماذج تنزل كبيانات) | كشف + OCR لصفحة في زمن مقبول |
| T3 | الترجمة عبر الـWorker مع السياق والمصطلحات + QC | فصل كامل READY، بلا اسم يتغير |
| T4 | الجدولة الذكية + READY_PARTIAL + العتبة المحسوبة | الدخول قبل الاكتمال، بلا توقف أثناء القراءة |
| T5 | المشاركة بين الأصدقاء + الذاكرة | صفحة مترجمة عند واحد تفتح فورًا عند الثاني |

### قرارات تحتاج المالك قبل T3

- **تكلفة الـAPI:** حد شهري وحصة لكل حساب.
- **النموذج:** جودة أعلى أو تكلفة أقل. T0 يعطي الأرقام قبل القرار.

## الترتيب المقترح

1. **F3 أولًا:** أصغرها وأسرعها وصولًا، وكل أساسه موجود (المجلس، الحضور، الإشعارات، القارئ المتصل). الجديد فقط Durable Object واحد.
2. **F1 ثانيًا:** يُنهي «إصلاح مصدر = APK»، ويستعمل نمط التحديث الذي بُني للتو.
3. **F2 ثالثًا:** أكبرها. يبدأ بـT0 (قياس) قبل أي التزام، لأن الأرقام تحدد أين يعمل كل جزء.
