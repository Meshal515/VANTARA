# إصلاح إضافات V7 — تحقق Debug أولًا

الفرع: `feat/addons-v7-native-manager-20261027`، طلب الدمج #298. لم يُنقل هذا التعديل إلى main أو Stable. إعداد الإضافات يستخدم helper النسخة القائمة، وهويتا Debug وStable وتوقيعاتهما مستقلتان.

## أسباب مثبتة وإصلاحاتها

- خطأ قوس في `source-verification.subscribe` منع تحميل الوحدة؛ أُعيد إنتاجه بالاختبارات قبل الإصلاح. الأحداث الخلفية تحدّث قائمة صامتة فقط، بلا Toast أو نافذة أو Activity تلقائية.
- كان انتهاء مهلة التحقق أو فشله يزيل السجل الأصلي، بينما الواجهة تحتفظ بطلب غير قابل لإعادة المحاولة. صار السجل يبقى `required` بتوكن جديد، ولا يُزال إلا بعد نجاح التحقق. لا فتح تلقائي ولا حذف cookies.
- فشل تحميل المحتوى بعد تحقق ناجح كان يُصنّف خطأ تحقق؛ فُصلت النتيجتان، دون اختلاق تحدٍّ جديد أو تكرار الطلب.
- V7 استخدم رابط إعداد خارجيًا بدل `configureLink/configureInApp` القائم. أُعيد استخدام مسار إعداد VANTARA نفسه؛ روابط الإعداد الشخصية لا تُسجّل.
- كان الرجوع من كتالوج المصدر يعيد إنشاء المدير بتبويب افتراضي. يُحفظ الآن snapshot للقائمة حسب الحساب والقسم، ويُستعاد التبويب والمستودع والبحث والموضع. الرجوع من جذر «المثبتة» يغادر المدير ولا يبدّل التبويب.
- بطاقات المانجا في شاشة المصدر كانت تطلب CDN مباشرة بلا جسر المصدر وترويساته وجلسته. صارت تستخدم `nativeCover` القائم، مع تجاهل النتائج المتأخرة ومنع fallback المباشر بعد فشل الجسر. صور الإضافات الخارجية تبقى على مسارها.
- كان مولد Spike يفشل بسبب روابط APK قديمة حُذفت. يستخدم وضع البناء الاختياري الحزم المتتبعة بعد فحص commit والفهرس والهوية وSHA؛ أعاد Kotlin نفسه لكل الحزم الست عشرة دون تغيير pins أو محرك التشغيل.

## الواجهة والأفعال

ثلاثة تبويبات بعدادات فعلية؛ الإضافات، المثبتة، تحتاج تحقق. زر الرجوع الخارجي فقط، قائمة أنواع ضمن الشاشة، شعارات حقيقية أو SVG محايد. المصدر المحتاج للتحقق يبقى مثبتًا ولا يفتح قبل الإجراء اليدوي. لا أخضر لمجرد التثبيت أو HTTP200، ولا أحمر لخطأ صورة أو فصل منفرد. نتيجة فحص الإضافة والتحديث تظهر داخل التفاصيل، والفحوص غير المنفذة تُصرّح بذلك. فحص الحزمة الأصلية يحل هويتها الحقيقية ثم يفوض إلى التشخيص الموجود؛ لا تخمين حسب الاسم ولا محرك بديل. تُلغى نتائج الفحص عند الإغلاق.

## اختبارات منفذة

- الويب: 1795/1795 اختبارًا في 198 ملفًا.
- سلامة المستودع: 54/54؛ بصمة Service Worker مجددة، دون مسح بيانات.
- سياسة التحقق الأصلية: JUnit مستقل 7/7؛ أدوات APK وSpike: Python 22/22؛ actionlint ناجح.
- Chromium فعلي: عروض 320 و375 و768 و1280 بلا تجاوز للقائمة أو أخطاء JavaScript. أزرار الفحص والتحديث والإعداد اختُبرت بنواتج معلنة محلية.
- shell الحقيقي: فشل إعادة إنتاج سابق عاد إلى التبويب الخطأ، ثم نجاح 30 دورة خلال 142.51 ثانية، مع تبويب العودة الصحيح وزر خارجي واحد وتحرير اللقطات بلا أخطاء JavaScript. المزامنة وخلفية المصدر محاكاة؛ هذا ليس اختبار Android أو تشغيل مواقع.
- فحص APK Debug المنشور السابق 2174: package وشهادة Debug الدائمة وhash والحجم توافق manifest. هذا لا يثبت صلاحية APK المرشح الجديد.

## مصادر وصور حية وحدود الإثبات

API Azora وغلاف JPEG معلن منه أعادا200؛ صورة1043533 بايت متطابقة بالترويسات وبدونها. MangaSwat أعاد403 مع `cf-mitigated: challenge` حتى بالترويسات الأصلية. لم يُتجاوز التحدي، ولم يُثبت عرض غلافه الحي أو تحقق مستخدم فعلي. فحص APK MangaSwat يثبت موارده الأصلية وترويساته؛ لا شعار عشوائي.

Android فقط ينفّذ حزم Mihon/Aniyomi عبر المحركات الموجودة. Windows/PWA يستخدمان تكاملاتهما المدعومة ولا ينفّذان DEX/APK؛ `.cs3` غير مدعوم تنفيذًا. لا تغييرات للتورنت أو الفيديو أو الحسابات أو بيانات المستخدمين.

## بوابة Android والنقل

يجب نجاح البناء واختبارات native وفحص شهادة APK والترقية فوق آخر Debug على المحاكي، مع فحص التخزين والهوية وLogcat. هذه البوابة لم تُستكمل لهذه الدفعة وقت كتابة التقرير؛ لا يُستنتج نجاح Android من Chromium. لم يُختبر جهاز فعلي أو تحقق CAPTCHA يدوي. لا نقل أو نشر Stable قبل اختبار Debug المطلوب ثم اختبار Stable مستقل مع إبقاء بياناته وجلساته وإعداد الإضافات فيه.
