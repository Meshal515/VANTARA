# VANTARA — استضافة كل مساحة على حساب صاحبها

> **رؤية مستقبلية قيد التصميم — 25 أكتوبر 2026.** هذه وثيقة تصورية لا تعني تفعيل التسجيل العام أو جاهزية التثبيت التلقائي. **لا تغيّر هذه الوثيقة كود التطبيق أو خدمات الإنتاج.**

## القرار

**صاحب VANTARA يطوّر البرنامج ويوزعه؛ صاحب المساحة يملك الاستضافة والبيانات والتكاليف.**

يستطيع أي شخص استخدام VANTARA وإنشاء مساحة خاصة لأصدقائه بعد إتاحة النسخة العامة. **كل مساحة** لها حساب Cloudflare يملكه مستضيفها، وتشمل Worker وD1 وDurable Objects عند الحاجة. بقية الأصدقاء يدخلون المساحة بالدعوة ولا يحتاج كل واحد منهم حساب Cloudflare.

لا ينقل التطبيق بيانات المساحات أو فيديوهات المستخدمين إلى حساب Cloudflare التابع للمطور. ولا يُنشئ المطور نيابة عن الناس آلاف الحسابات بقصد مضاعفة الحصة المجانية.

## شرط المنتج المالي

**هدف التشغيل لصاحب مشروع VANTARA = صفر رسوم استضافة مترتبة على استخدام المساحات الخاصة مهما بلغ عدد المستخدمين.** يتحقق هذا التصميم فقط إذا كان كل صاحب مساحة يملك مواردها مباشرة وليس وراءه خادم مركزي إلزامي يستهلك مع كل مستخدم.

- حساب Cloudflare الخاص بالمستضيف يبدأ بالخطة المجانية إن كانت الموارد المطلوبة ضمن حدودها.
- إذا احتاج المستضيف أكثر من الحصة المجانية، يقرر بنفسه الترقية والدفع لـCloudflare؛ لا تُخصم أي فاتورة من حساب المطور.
- على الخطة المجانية، تجاوز حدود بعض الموارد يُوقف طلبات/عمليات إضافية حتى التجديد، ولا يرفع الخطة أو يخصم رسومًا تلقائيًا.
- خدمة اختيارية مدفوعة أو إضافة لها ترخيص خارجي لا تصبح مجانية تلقائيًا لأن VANTARA مجاني.
- تحديثات الشيفرة يمكن توزيعها عبر مستودع عام؛ **تكاليف وقت التطوير والدعم والتوزيع والخدمات الاختيارية** ليست بالضرورة معدومة، ولا يجوز الوعد أن جميع تكاليف المشروع ستظل صفرًا في كل ظرف.

## أرقام Cloudflare المرجعية (أكتوبر 2026)

| المورد | خطة Workers Free |
| --- | --- |
| طلبات Worker | 100,000 طلب يوميًا لكل حساب |
| D1 — قراءة | 5 ملايين صف يوميًا |
| D1 — كتابة | 100,000 صف يوميًا |
| D1 — تخزين | 5 جيجابايت إجماليًا |
| Durable Objects | متاحة مع تخزين SQLite وحدود مجانية |
| رابط مساحة | عنوان `workers.dev` مجاني ضمن خدمة Workers |

**عمال Workers Paid** يبدأون من **5 دولارات أمريكية شهريًا لكل حساب**، مع حصص وفواتير إضافية بحسب الاستهلاك. **المبلغ ليس اشتراكًا إجباريًا عند إنشاء كل مساحة.**

مصادر الأسعار والحدود: [Workers](https://developers.cloudflare.com/workers/platform/pricing/) · [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/) · [D1](https://developers.cloudflare.com/d1/platform/pricing/) · [Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/).

## هل Cloudflare تسمح بنسخ كثيرة من VANTARA؟

تدعم Cloudflare رسميًا زر [Deploy to Cloudflare](https://developers.cloudflare.com/workers/platform/deploy-buttons/) لإنشاء نسخة مشروع من مستودع عام داخل **حساب المستخدم نفسه** مع إنشاء موارد D1 وDurable Objects التي يعلنها المشروع وفق الشروط والأدوات المدعومة.

قد تتعرف Cloudflare على أن النسخ تستعمل نفس القالب، وهذا لا يعني بحد ذاته مخالفة. لكن **لا ضمان مسبق بأن مليون نشر سيُقبل بلا قيود أو مراجعات أو ضوابط أمنية**. يجب أن يكون لكل حساب مالك حقيقي يستخدم خدماته وفق شروط Cloudflare، مع تجنب إنشاء حسابات صورية للتحايل على الحدود.

## واجهات الاستخدام — لا PWA عامة الآن

**قرار النطاق الحالي:** لا نطلق خدمة PWA عامة عند فتح الاستضافة الذاتية. التركيز يكون على تطبيق **Android وWindows** والخدمات الخلفية التابعة لكل مستضيف.

- تطبيق Android أو Windows العام يربط المستخدم بعنوان `Worker` الخاص بمساحته بعد فحص هوية الخدمة والموافقة على الربط.
- **iPhone:** لا يوجد عميل iOS أصلي مثبت في المستودع الحالي. إذا لم تُتح PWA، فيجب تطوير عميل iOS مناسب قبل ادعاء دعم الآيفون؛ وأي نشر عبر متجر Apple قد يترتب عليه اشتراك مطور/تكاليف توزيع.
- يمكن إبقاء PWA أداة تطوير أو ميزة اختيارية مستقبلية إذا أثبتت الحاجة إليها، لكنها ليست جزءًا إلزاميًا من النموذج الحالي.
- مجرد تحديث README لا يغلق خدمة PWA منشورة بالفعل؛ تعطيلها في الإنتاج إجراء مستقل يتطلب موافقة ونطاق عمل تقني.

## التحديثات عبر حسابات Cloudflare المستقلة

المشروع الرسمي ينشر **إصدارًا واحدًا موثوقًا** للحزم والكود وعقود API. يختار المستضيف إن كان يريد تحديث خدمته تلقائيًا أو بموافقة يدوية:

1. تخرج نسخة موثقة من VANTARA برقم إصدار وبصمات/توقيع مناسب.
2. نظام نشر تابع لحساب المستضيف يراجع التحديث وتوافقه مع إعدادات المساحة.
3. تجري اختبارات وترحيلات D1 الآمنة مع نسخة استعادة/خطة تراجع قبل التغييرات الخطرة.
4. ينشر المستضيف Worker الجديد على عنوان المساحة **نفسه**. لا يحتاج مطور VANTARA إلى مفتاح Cloudflare الخاص به.
5. Android وWindows يتحدثان عبر قناة توزيع عامة مستقلة، مع سياسة توافق بين إصدار التطبيق وإصدار Backend.

زر Deploy to Cloudflare يسهل **النشر الأولي**، لكنه وحده لا يضمن مزامنة جميع النسخ المنسوخة مستقبلًا؛ يجب تصميم أداة تحديث أو تكامل GitHub من حساب المستضيف.

**لا تجمع أسرار المستضيفين أو مفاتيح API في خادم مركزي للمشروع.** ولا تسمح بتحديث غير متوافق بأن يفسد D1 حتى لو أمكن الرجوع لإصدار Worker أقدم.

## قائمة المتطلبات قبل إتاحة المنتج للجميع

- [ ] قالب نشر مستقل للـSync Worker وD1 وDurable Objects، دون عنوان مزامنة تابع للمطور.
- [ ] تدفق إنشاء مساحة ودعوات ومصادقة متوافق مع مجموعات منفصلة وبدون كشف حسابات غير مدعوة.
- [ ] ربط تطبيق Android/Windows بخادم يختاره صاحب المساحة.
- [ ] إعداد Secrets لكل مستضيف في حسابه، بأقل الصلاحيات.
- [ ] إصدار عام قابل للتحقق وآلية تحديث بخيار يدوي أو تلقائي وتوافق API/Data.
- [ ] تخفيف وتيرة Polling والحضور والكتابات إلى حدود الحساب المجاني؛ في الكود الحالي توجد عمليات حضور متكررة كل 5 ثوانٍ عند عرض شاشة الأصدقاء.
- [ ] اختبارات مساحات مستقلة على حسابات تجريبية منفصلة، وتجربة وصول limits مع الحفاظ على بيانات المستخدم.
- [ ] تحقق مستقل من التراخيص القانونية للكود والتبعيات قبل وصفه بالمصدر المفتوح.
- [ ] التأكد من أن تشغيل الأنمي/السينما/المانجا يتم على الأجهزة أو من موصلات المستخدم، وليس بث الوسائط عبر خادم صاحب المساحة.

## معيار النجاح

توجد نسختان على حسابي Cloudflare مستقلين. كل نسخة تشغّل بيانات مجموعتها ودعواتها وغرفها، وتستقبل تحديثًا موثوقًا من VANTARA، مع بقاء البيانات مفصولة، **دون أي مفاتيح للمستضيفين أو موارد تشغيل تخص حساب المطور**.

**هذه طريقة للوصول إلى صفر تكلفة استضافة لكل مستخدم على صاحب المشروع، وليست ضمانًا بأن كل مستضيف لن يدفع أبدًا أو بأن Cloudflare تضمن عددًا غير محدود من الحسابات.**
