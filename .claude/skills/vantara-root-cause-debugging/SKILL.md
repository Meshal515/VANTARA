# vantara-root-cause-debugging

هذه مهارة أصلية مكيّفة مع VANTARA، وليست استيرادًا أو نسخة من مهارة خارجية. اقرأ `CLAUDE.md` والملفات المعنية قبل التعديل. التزم بموافقة المالك قبل الدمج أو النشر، واحترم حدود المهمة.

## سير العمل
1. حدّد السلوك المتوقع والفعلّي وبيئة الاختبار وشبكة الجهاز ونسخة Debug/Stable وcommit.
2. اتبع خطّ التتبع من ضغط المستخدم حتى المصدر/المحرك/الجسر/الواجهة، وسجّل الزمن ونقطة الفشل.
3. اختبر الفرضيات واحدة تلو الأخرى. قارن المسار العامل بالمسار الفاشل، ولا تعالج الأعراض برفع timeout.
4. أصلح أقل تغيير يعالج السبب، ثم نفّذ اختبارات الوحدات، التكامل، والسيناريو البشري إن توفّر.
5. أصدر تقريرًا: السبب المؤكد، الملفات المتغيرة، النتائج، وما بقي غير مختبر.

## معيار اكتمال المهمة
- وجود إعادة إنتاج واضحة أو بيان لماذا تعذّرت؛ لا استنتاج عطل من مخرجات مبهمة.
- وجود اختبار فشل قبل الإصلاح ونجح بعده، أو دليل بديل موثّق عند تعذّر الأتمتة.
- التأكد من المسارات الشقيقة والسباقات والتكرار والبيانات المتأخرة.

## قواعد مشتركة
- ابدأ بإثبات الحالة الحالية: فرع/commit، مسار التنفيذ، وأدلة قابلة للتكرار.
- لا تُعلن نجاحًا اعتمادًا على كتابة الكود أو CI فقط؛ حدّد ما نُفّذ وما اختُبر فعليًا.
- لا تثبّت سكربتات أو مهارات خارجية تلقائيًا. راجع المصدر والترخيص وملف SKILL.md والأذونات أولًا.
- حافظ على البيانات المحلية والمصادر ومحركات الوسائط المستقرة، ولا توسّع نطاق التغيير دون حاجة.
- وثّق الخطأ وسبب جذره وتغييرات الملفات والاختبار الراجع والقيود. التواصل بالعربية.
